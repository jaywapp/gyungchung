# 경기광주·용인·성남 풋살장 프리셋

자료 확인일: **2026-10-02**. 범위는 경기도 세 도시의 행정구역 내부다. 광주광역시와 인접 도시는 포함하지 않았다.

| 지역 | 구장·코트 선택지 |
| --- | ---: |
| 광주시 | 14 |
| 용인시 | 60 |
| 성남시 | 23 |
| 합계 | **97** |

`regional-futsal.json`이 정제 원본이다. 아이엠그라운드 현행 코트 66개와 공공·운영자·다른 공개 예약 출처로 보완한 31개를 담았다. 실내/야외, A/B면, 층별 코트 식별자가 있으면 분리한다. 공공 시설의 코트 구분을 확인할 수 없으면 시설 하나를 선택지 하나로 둔다. 97은 시설 건물 수가 아니다.

장소 사실만 저장했다. 사진, 후기, 홍보 설명은 복제하지 않았다. 좌표가 확인되지 않은 구장은 `null`이다. 출처 조회일은 현장 영업 확인일이나 예약 가능 보장이 아니다.

## 조사 범위와 완전성

- [아이엠그라운드 공개 예약 페이지](https://web.iamground.kr/68)가 사용하는 공개 목록 API를 조회했다. 로그인이나 회원 데이터는 사용하지 않았다.
- 2026-10-02·03·04·05·09·16·23·30일 각각 06:00부터 다음날 06:00까지, `FUT`/`MATCH`, `size=200`, 세 도시 검색어로 **24회** 조회했다. 주소가 해당 도시인 코트만 채택했다.
- 각 요청은 `total_pages=1`이고 반환 수와 `total_count`가 같았다. [요청 감사 파일](./iamground-request-audit.json)에 URL·건수·확인 시각을 보관했다. 공식 UI도 200개 미만이면 추가 조회를 종료한다. API에서 강제로 `page=1`을 넣으면 첫 코트만 빠지는 비표준 동작이 있어 임의 페이지 반복으로 전수 수집을 주장하지 않는다.
- 합집합 68코트의 고유 `facility_id` 51개를 공개 시설 상세로 대조했다. 추가 코트는 없었고 개인 트레이닝존 2개는 제외했다.
- [광주시 체육시설](https://www.gjcity.go.kr/depart/gym/list.do?mId=0701010000), [용인시 공공체육시설](https://publicsports.yongin.go.kr/), [성남시 체육시설 신청](https://www.seongnam.go.kr/apply/sports/step1?facilityId=S0008&instiCode=PARK_13), 운영자 안내와 플랩 공개 구장 정보를 보완했다. 각 행의 `source_urls`가 구체적 근거다.

공개 예약 달력은 날짜별 일정 노출에 따라 달라진다. 예약 목록에 노출되지 않는 시설, 비공개 구장, 최근 개폐업을 포함한 **실제 모든 풋살장을 보장하지 않는다**. 과거 페이지 검색 색인만 있는 시설은 현행 자료로 취급하지 않았다.

## 중복 처리와 보류

- 세븐 실내: 동일 이름·도로명·실내 유형으로 IAM 1220과 플랩을 합쳤다. 기존 DB `세븐풋살장`의 ID·이름·짧은 주소·메모·생성자는 보존하고 도시·출처를 추가했다.
- 메이저 2호점 야외: 동일 기본 도로명 `포은대로 1100-36`, 고유 이름·야외 유형으로 IAM 1305와 플랩을 합쳤다. 실내 1306은 별도다.
- DP: 플랩 `도평리 82`와 IAM `도평길110번길 19-10`의 직접 주소 대응·코트 동일성 미확정. 현행 IAM 코트는 등록하되 플랩 항목의 추가 생성·확정 별칭은 보류했다.
- 참스포츠/리더스: 같은 `지삼로 51-1` 소재지이나 플랩 코트를 IAM 실내/야외 중 하나로 대응할 근거가 부족하다. IAM 두 코트를 등록하고 추가 플랩 항목은 보류했다.
- 킹주니어와 그린호크 야외는 각각 사송동 482와 327-2로 다른 장소라 별도 등록했다. 상호의 `분당`을 행정 주소로 사용하지 않았다.

`pending-verification.json`의 **15개 후보**는 트레이닝 2개, 위 중복 가능 항목 2개, 현행 확인이 부족한 과거 시설 11개다. 보류가 폐업 판정을 뜻하지 않는다. 후보는 운영 DB에 넣지 않았다.

## 재생성과 검사

1. 확인된 사실을 JSON에 갱신한다. IAM 키는 `iamground-{stadium_id}`, 보완 자료 키는 장소별 고정 키다. 키를 임의로 바꾸지 않는다.
2. Supabase CLI `migration new`로 새 파일을 생성한 뒤 `node scripts/build-venue-preset-seed.mjs data/venue-presets/regional-futsal.json <migration.sql>`을 실행한다.
3. 외부 검증 환경의 PGlite 모듈 경로를 `VENUE_PGLITE_MODULE`로 지정하고 `node scripts/verify-venue-presets.mjs`를 실행한다. 이 스크립트는 이번 고정 시드·스키마 회귀 검사용이다. 후속 마이그레이션의 검증은 별도로 추가한다.

시드는 키→확정 이름·주소/별칭 순서로 기존 행을 연결한다. 모호한 중복은 실패시키고, 기존 수동 필드와 이벤트 스냅샷은 변경하지 않는다. 재적용은 ID·행 수를 보존하지만 기존 트리거에 의해 `updated_at`은 갱신될 수 있다.
