# 일정별 Player of the Match 설계
작성일: 2026-10-05

## 데이터 계약
- events.ends_at: nullable timestamptz. NULL은 기본 종료 시각 starts_at + 2시간을 뜻하며 실제 종료를 확인한 이력으로 간주하지 않는다. starts_at보다 뒤여야 한다.
- events.mom_voting_days: integer NOT NULL DEFAULT 3, 1~30일. 일정별 설정이며 하루는 24시간이다. 개시=coalesce(ends_at, starts_at+2시간), 마감=개시+days*24시간. [개시,마감) 동안만 투표 가능하다.
- 기존 표를 삭제/재작성하지 않는다. 새 일정은 종료 시각을 편집하고, 반복 등록은 시작·종료 모두 동일한 간격으로 이동한다. 주간 자동 일정은 NULL의 기본 종료 기준을 따른다.
- 기존 event_mom_votes own SELECT/direct upsert 계약은 이전 설치 앱과 호환되도록 유지한다. 서버가 INSERT/UPDATE/DELETE 모두에 마감·본인·자격을 검사한다. UPDATE로 event_id/voter_id를 바꿀 수 없다. 표 변경과 일정 설정 변경은 동일 이벤트 행 잠금으로 충돌을 제어한다.
- 투표 actor는 인증 연결된 활동·비숨김·초기비번 변경 완료 회원. candidate는 활동·비숨김·실제 출석/지각 회원이며 본인은 제외. 개인 표 읽기와 결과 조회에도 actor 경계를 적용한다.
- 결과 RPC 5열 반환형과 공동 순위 유지. 진행 중 결과는 현재 집계, 마감 후 결과는 최종 집계로 표시한다. 서버 시계가 최종 투표 가능 여부를 결정한다. 결과에 attendance JOIN을 추가하거나 출석 수정으로 기존 표를 지우지 않는다.
- 누적 MOM 집계는 마감된 일정만 포함해 임시 1위를 최종 수상으로 세지 않는다. 기존 시즌 MVP(우승 명단)·득점·출석과 독립이다.
- 익명에게 표나 회원 결과를 공개하지 않는다. 기본 EXECUTE 회수, private guarded definer, 고정 search_path 및 기존 events.manage 권한을 사용한다.

## 화면 계약
기존 매치 콘솔, Pretendard/navy/lime와 기존 버튼·아이콘을 따른다. 일정별 종료/마감, 대기·진행·마감 상태, 현재 선택, 현재/최종 결과, 표가 없는 상태를 표시한다. 관리 입력은 기존 일정 수정에 넣으며 events.manage를 사용한다. 모든 운영진은 기본 접근하되 시스템 관리자의 서비스 권한 설정을 존중한다.

모달 열린 중 마감·권한·계정·일정 삭제/변경을 제출 직전에 확인한다. 시간 갱신과 서버 거절을 통해 늦은 투표를 안내하고 다시 조회할 수 있다. 서버 필드가 없는 구형 조회는 투표 기준 미확인으로 처리해 무기한 투표를 안내하지 않는다. 초기 리소스는 기존 events/momVotes/momResults를 사용한다.

모바일 변경은 미발행 0.1.5의 생일·전화 변경과 합산한다. 새 네이티브 의존성은 추가하지 않는다.
## 호환과 일괄 확인 범위
- 기본 경기 시간 질문의 선택이 제출되지 않아 기존 주간 안내 기준 2시간으로 진행한다. 운영진은 일정별 종료 시각을 입력해 변경한다.
- 관리자가 종료 시각/기간을 바꾸면 마감도 다시 계산되며, 이미 마감된 투표가 재개될 수 있다는 안내를 편집 화면에 둔다.
- 일정/회원 삭제에 따른 기존 FK cascade는 부모 삭제 권한에 따라 계속 동작한다. 직접 개인표 DELETE의 마감 검사와 구분한다.
- 합성 검증은 실제 종료 직전/정각, 72시간 직전/정각, 1~30일 유효성, 반복 일정 시간 이동, 마감 열린 모달, 서버 거절 후 조회, 계정 전환/ABA, 권한 회수, 구형 서버/필드 누락, 무표/공동1위, 과거 표 보존, cascade와 직접취소, 생일·전화 및 기존 초기조회 수를 포함한다. 지금 실행하지 않는다.
## 서버 잠금·취소 예외
투표가 먼저 표 행을 잡은 뒤 일정 삭제와 서로 기다리는 상황을 피하도록 이벤트 FOR SHARE NOWAIT를 사용한다. 일정 설정/삭제와 충돌하면 40001로 거절하고 최신 일정·투표를 조회한 뒤 재시도한다. 직접 개인표 취소는 기간과 본인 투표자 자격/출석을 확인하되 후보가 비활동으로 바뀌었다는 이유만으로 기간 내 취소를 막지 않는다. FK cascade는 중첩 트리거와 실제 부모 소멸이 모두 확인된 경우만 별도로 통과시킨다.

종료 시각이 기본값인 일정도 시작시각 이동으로 마감이 바뀌므로 starts_at/ends_at/mom_voting_days의 관리 변경에는 현재 연결·활동·초기비번 변경·비숨김 자격과 events.manage를 함께 확인한다. 서버 자동 주간 생성은 기존 서비스 실행 경로를 보존한다.
## 최신 자격 회복
서버 거절에는 마감뿐 아니라 회원 상태/출석 변경도 포함된다. 개인 표·집계·일정만 조회하면 후보 명단이 그대로 남아 재거절될 수 있으므로 명시적 재조회/거절 회복은 profiles와 attendance도 함께 조회한다. 모바일 경계 통과의 자동 조회는 events/momVotes/momResults 3개, 저장 성공은 momVotes/momResults 2개를 유지한다. 모바일 거절/수동 회복은 events/profiles/attendance/momVotes/momResults 5개다. 웹 상세 페이지 복구는 오류 의존성을 포함해 events/memberDirectory/profiles/attendance/momVotes/momResults 6개로 좁힌다. 모든 조회는 기존 owner/epoch 경계를 존중하며 지금 실행 검증하지 않는다.
웹의 일반 회원 후보 명단은 memberDirectory에서 합쳐진다. 해당 조회 실패도 상세 화면 오류/제출 전 오류에 포함해 실패를 후보 없음으로 표시하지 않는다. 모바일은 profiles 리소스 안에서 directory와 본인 profiles 두 조회를 함께 관리한다.
