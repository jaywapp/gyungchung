## 4. 테스트 중 발견하고 수정한 결함

### BUG-01 경기 기록 저장 버튼이 팀 재편성으로 처리됨

- 재현: 팀 편성 관리에서 스코어·골·평점을 입력하고 `경기 기록 저장` 클릭
- 원인: `new FormData(form)`에는 클릭한 submit 버튼의 `name/value`가 포함되지 않아 기본 동작인 팀 생성으로 분기됨
- 수정: React submit 이벤트의 `nativeEvent.submitter`로 실제 클릭 버튼을 판별
- 반영 PR: https://github.com/jaywapp/gyungchung/pull/8
- 재검증: 2:4 스코어, 승패, 1골·2골, 7.5·8.5·9.0 평점이 운영 일정 카드에 표시됨

### BUG-02 의견 접수 뒤 폼 초기화 단계에서 오류 발생

- 재현: 사용자 의견을 접수하면 DB 저장은 성공하지만 폼과 접수 목록이 갱신되지 않음
- 원인: 비동기 저장 후 React 이벤트의 `currentTarget`이 `null`이 된 상태에서 `reset()` 호출
- 수정: 저장 전에 폼 엘리먼트를 지역 변수로 보관하고 해당 참조로 초기화
- 반영 PR: https://github.com/jaywapp/gyungchung/pull/9
- 재검증: 폼 초기화, 접수 내역 노출, 운영진 답변 공개까지 정상 동작

### BUG-03 기존 소셜 계정 이메일로 비밀번호 회원가입 후 로그인 실패

- 재현: Google 계정과 같은 이메일로 이메일·비밀번호 회원가입 후 비밀번호 로그인 시도
- 증거: Auth 로그에서 회원가입은 `user_repeated_signup`과 HTTP 200, 로그인은 `invalid_credentials`와 HTTP 400으로 기록
- 원인: Supabase가 사용자 열거 공격을 막기 위해 중복 가입에도 성공처럼 응답하지만 기존 OAuth 계정에는 새 비밀번호를 설정하지 않음
- 수정: 로그인 화면에 비밀번호 설정·재설정 기능과 복구 메일 콜백 뒤 새 비밀번호 저장 화면 추가
- 반영 PR: https://github.com/jaywapp/gyungchung/pull/13
- 재검증: 운영 복구 요청이 `user_recovery_requested`와 HTTP 200으로 기록되고 기존 어드민 Google 세션 복원 완료

## 7. 이번 실행에서 제한한 항목

- Google OAuth 리다이렉트와 기존 어드민 세션 복원은 재검증했다. Kakao는 로그인 버튼, 콜백 라우트, 배포 환경 설정과 기존 성공 로그를 확인했다.
- 별도 매니저 계정 로그인은 실행하지 않았다. 매니저 권한표, 회원 승인 고정 권한, RLS의 `events.manage`·`members.manage` 검사는 확인했다.
- 공개 중인 선거·투표·설문 데이터가 없어 이번 실행에서는 빈 상태까지만 확인했다. 참여 저장 RPC와 관리 화면은 기존 구현을 유지한다.

신규 용병, 실제 출석, 활동 랭킹, MOM, 랜덤·균형 팀 편성, 커피 내기 경기 기록과 이메일·비밀번호 인증 기능은 운영 환경에서 정상 동작한다. 이메일 가입은 인증 메일 확인 뒤 가입 신청서를 작성하고, 매니저 이상 승인 후 회원 기능을 이용하는 기존 절차와 연결된다. 기존 소셜 계정과 같은 이메일에는 비밀번호 설정·재설정으로 비밀번호 로그인을 추가할 수 있다. 테스트에서 발견한 결함은 수정·main 병합·프로덕션 재배포 후 같은 Chrome 시나리오로 재검증했다.
