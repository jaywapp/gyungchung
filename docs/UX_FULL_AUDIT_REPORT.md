## 1. 총평

1. 홈은 서비스 목적, 다음 일정, 장소, 정원, RSVP를 한 화면에서 확인할 수 있었다.
2. 일정 목록과 생성된 일정 딥링크(`/events/YYYYMMDD`)는 정상적으로 날짜·상태·참석 정보를 보여 주었다.
3. 회비·공지·랭킹·참여 화면은 정상 데이터와 빈 데이터를 서로 구분해 표시했다.
4. 모바일 320px부터 데스크톱 1440px까지 전체 페이지 가로 overflow는 재현되지 않았다.
5. 모바일 메뉴는 키보드 Enter로 열리고 Escape로 닫혔다.
6. 잘못된 날짜 형식(`/events/2026-08-23`)은 404로 안전하게 복귀했고, 제품이 생성하는 형식(`/events/20260823`)은 정상 동작했다.
7. 현재 운영 URL에는 읽기 전용 확인을 방해하는 치명적 오류를 확정할 만한 증거가 없었다.
8. 다만 격리된 테스트 프로젝트와 역할별 계정이 없어 제출·수정·삭제·권한 제한·OAuth 복귀·피드백 외부 연동은 검증하지 못했다.
9. 운영 세션의 개인정보와 실제 변경을 보호하기 위해 RSVP, 설문 제출, 피드백 제출, 관리자 변경, 비밀번호 저장은 실행하지 않았다.
10. 결론은 “확인된 S0/S1 결함 없음, 핵심 변경 과업은 미검증 범위가 큼”이다.

## 2. 가장 치명적인 사용자 마찰

현재 안전한 읽기 전용 점검에서 C2 이상으로 확정된 S0/S1 결함은 없었다. 다음은 결함이 아니라 검증 공백이다.

- 역할별 계정이 없어 비로그인, 프로필 미연결, 승인 대기, 비활성 회원, 일부 운영 권한 상태를 같은 과업에서 비교하지 못했다.
- 격리 데이터가 없어 RSVP 변경, 참여 폼 제출, 초안 보존, 결과 공개, 권한 일괄 변경의 성공·실패·재시도 상태를 종단간 확인하지 못했다.
- `/feedback`, 인증 콜백, 외부 GitHub 연결은 운영 쓰기 또는 외부 동기화 가능성이 있어 실행하지 않았다.

## 3. 잘 작동하는 경험

- 홈의 다음 일정 카드가 날짜, 시간, 장소, 네이버 지도 링크, 정원 현황, 회원·용병 수, RSVP 상태를 함께 제공했다.
- 일정 상세가 예정 일정과 지난 일정을 구분하고, 예정 일정에는 참석 유지 행동, 지난 일정에는 출석·MOM·팀 결과 정보를 보여 주었다.
- 회비 화면의 등록 내역 없음 상태가 수치와 안내 문구를 함께 제공해 빈 데이터와 로딩을 혼동시키지 않았다.

## 8. S0·S1 상세 및 캡처

S0 또는 S1로 확정된 항목이 없어 상세 캡처는 없다. 운영 세션 화면에는 회원 식별 정보가 포함될 수 있어 캡처 파일도 보고서에 첨부하지 않았다. 대신 비식별 DOM 근거와 반응형 측정값을 기록했다.

- 홈 정상 상태: H1, 일정 카드, 장소 링크, 정원 현황, RSVP 버튼, 공지 카드 확인.
- 예정 일정 상세: `/events/20260823`, 예정 상태·정원·팀 결과 확인.
- 지난 일정 상세: `/events/20260816`, 지난 상태·출석·MOM·팀 결과 확인.
- 반응형: 320/360/390/768/1024/1440px 모두 `document.scrollWidth <= window.innerWidth`.
- 키보드: 모바일 메뉴 Enter 열기, Escape 닫기 확인.

- 회비 빈 상태가 수치와 안내 문구를 함께 표시함.
- 일정 달력이 일정 있음/없음/오늘을 접근 가능한 이름으로 구분함.
- 예정/지난 일정이 다른 상태 문구와 행동으로 구분됨.
- 장소 링크가 네이버 지도 링크로 명확하게 노출됨.
- 404 화면이 원인과 홈 복귀 링크를 제공함.
- 모바일 메뉴의 접근 가능한 이름과 `aria-expanded` 상태가 바뀜.

## 10. 미검증 범위와 필요한 계정·데이터

다음 조건이 준비되어야 종단간 점검을 완료할 수 있다.

- 격리된 Supabase 프로젝트 또는 폐기 가능한 DB 브랜치와 별도 운영 URL.
- 비로그인 방문자 세션.
- 회원 프로필 미연결 계정.
- 승인 대기·비활성·거절 상태 계정.
- 승인된 일반 회원 2명 이상과 정원 임박 일정.
- 일부 운영 권한만 가진 회장·부회장·총무 계정과 시스템 관리자 계정.
- 예정 일정, 지난 일정, 빈 일정, 정원 초과 방지용 일정.
- 진행 중·마감·결과 공개·비밀 투표·필수 복수선택을 포함한 참여 항목.
- GitHub 연결 성공·실패를 분리해 확인할 수 있는 테스트 저장소와 Edge Function 설정.
- OAuth 제공자 테스트 계정과 공유 일정 deep link.
- 회비·공지·회원·출석·팀 편성·권한 변경의 폐기 가능한 시드 데이터.

실제 스크린리더, WCAG 명암 측정, 브라우저 200% 확대, 모바일 가로모드, 네트워크 장애 주입도 이 실행에서는 완료하지 않았다. 현재 브라우저 도구로 확인한 것은 세로 대표 폭과 읽기 전용 화면뿐이다.

## 11. 결함과 분리된 개선 기회

- 공유 URL 계약을 사용자 문서나 복사 가능한 공유 UI에 명시하고, 사람이 입력한 `YYYY-MM-DD`도 정규화할지 제품 결정한다.
- 첫 방문 화면의 가장 중요한 다음 행동과 로그인·승인 안내를 비로그인 세션에서 별도 검증한다.
- 참여·피드백·권한 변경에 대해 성공, 부분 성공, 실패, 재시도, 입력 보존을 역할별 테스트 시나리오로 고정한다.
- 모바일 200% 확대와 실제 스크린리더 검증을 별도 접근성 패스로 수행한다.
