# 계정 프로필 사진 설계

기존 마이페이지·Sheet와 회원 아바타를 확장하며 현재 테마·색·서체·이니셜 대체 표시를 따른다. 새로운 주요 화면이나 시각 체계를 만들지 않는다. 사진 선택·진행 중·취소·성공·오류·제거 상태와 접근성 이름을 제공한다.

## 데이터·권한
profiles.avatar_path에 nullable 경로만 저장한다. private profile-avatars bucket은 JPEG·1 MiB로 제한한다. 경로는 본인 auth UUID/새 UUID.jpg이며 덮어쓰지 않는다. SELECT는 활동 회원의 현재 사진과 본인 객체에 제한하고 INSERT/DELETE는 본인만 허용한다. UPDATE Storage 정책은 만들지 않는다.

set_profile_avatar(next_avatar_path, expected_avatar_path)는 본인 활동 프로필·초기 비밀번호 변경 완료를 재확인하며 객체 소유자·형식·크기를 검사한다. 기존 경로와 expected가 다르면 40001로 거절한다. public invoker RPC와 private guarded definer를 사용한다. 일반 프로필 API에서 사진 경로를 직접 지정하는 행위는 trigger로 차단한다. 회원 디렉터리의 사진 경로 추가 시 기존 회비 기준 숨김과 ACL을 유지한다.

## 이미지와 비동기 처리
웹은 JPEG/PNG/WebP 10 MiB 이하 입력을 중앙 정사각형·512px 이하 JPEG로 다시 인코딩한다. 앱은 시스템 사진 선택기와 양 OS 지원 Expo 이미지 처리 모듈을 사용하고 최종 ArrayBuffer를 업로드한다. 원본 메타데이터는 보존하지 않는다.

업로드 완료 뒤 CAS RPC로 사진을 전환한다. 실패하면 새 파일을 SDK로 정리하고 기존 경로를 유지한다. 성공 후 기존 파일을 SDK로 정리한다. 제거도 경로를 먼저 null로 바꾼다. Storage 객체를 운영 SQL로 지우지 않는다.

서명 URL은 300초이며 경로들을 일괄 서명하고 짧게 메모리 캐시한다. 서명 URL은 발급 후 만료까지 유효하므로 외부로 복사된 URL을 즉시 회수한다고 보장하지 않는다. 앱 화면과 캐시는 로그아웃·계정 변경·활동 권한 상실 시 즉시 비운다. 매 await 단계에서 소유자 일치 여부를 확인해 이전 계정의 결과·알림을 무시한다.

웹 서버 변경은 웹 저장소에서 관리한다. Android를 우선 검증하며 Android 결과를 iOS 설치·동작 검증으로 표시하지 않는다.
현재 참조 중인 Storage 객체의 DELETE도 차단한다. 사진 변경 RPC와 삭제 검사는 동일한 본인 프로필 행 잠금으로 직렬화하여 동시 삭제·경로 지정 경합을 막는다. RPC 응답이 유실되면 현재 경로를 재확인하고, 결과를 확인하지 못한 파일은 삭제하지 않는다. 계정이 바뀌면 이전 계정의 파일 정리 요청도 보내지 않는다.
