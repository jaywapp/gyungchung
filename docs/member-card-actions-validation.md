사용자 지시로 웹을 먼저 검증·배포한다. 모바일 구현은 로컬 준비 상태로 유지하고 이번 단계에서는 앱 검사·빌드·PR·APK 발행을 하지 않는다.

## 실행 결과

- 전체 웹 테스트: 330개 중 329 pass, 기존 1 skip, 실패 0. 새 회원 메뉴·관리 actor·전화 조회·vCard 및 Blob 정리 회귀를 포함한다.
- TypeScript --noEmit: exit 0.
- ESLint: exit 0, 오류 0, member-directory의 effect 의존성 경고 2개. 대상/actor generation을 기준으로 정리하는 기존 설계이며 독립 소스 리뷰에서 동작 오류는 발견하지 않았다. selectedProfile 객체를 단순 의존성으로 추가하면 재조회 중 준비된 연락처가 사라질 수 있어 이번 범위에서 변경하지 않았다.

Windows npm 실행기의 `Unknown command: pm` 오류는 설치된 ESLint·Next CLI를 Node로 직접 실행해 우회했다. 테스트 소스를 약화하거나 검사를 생략하지 않았다.

원로그·화면·합성 브라우저 결과와 검증 대상 소스 SHA256은 커밋하지 않는 .ux-review/member-card-actions/에 보관한다. 브라우저·최종 리뷰·PR·운영 결과는 확인 후 아래에 추가한다.

## 확인 범위

회귀 테스트는 실제 제품 AST에서 핸들러와 렌더를 추출하고 RPC/OS 동작을 대역으로 처리한다. 실제 React effect·브라우저 포커스·다운로드는 별도 합성 UI 확인 대상이다. 실제 회원 DB 쓰기, 전화 앱 발신 및 기기 주소록 가져오기는 수행하지 않는다. 웹은 vCard 내려받기 후 사용자가 연락처 앱에서 저장하는 기능이다.

## 생산 빌드 브라우저 확인

기존에 기록한 in-app Browser 초기화 실패의 headless Chromium 대체 경로로 생산 빌드를 한 번 확인했다. 데스크톱 1440×1050와 모바일 390×844에서 합성 로그인·REST/API 가로채기·WebSocket 차단 환경의 116개 확인이 통과했다. 페이지 오류·예상 밖 콘솔 오류·외부 요청·회원 DB 쓰기 시도는 모두 0이다. 의도한 번호 조회 503 실패의 콘솔 메시지 2개만 기록했다.

카드별 단일 전체 선택 버튼, 상시 전화 버튼 제거, 상세·연락 메뉴, Escape 포커스 복귀·포커스 제한, 선택 시 단일 번호 조회, 실제 한국어·emoji 이름의 UTF-8 vCard 내려받기, 번호 없음/오류, 중복 요청 및 메뉴 A-B-A 뒤 늦은 결과 폐기를 확인했다. 운영진과 숨김 QA 관리자의 수정 editor·강퇴 확인 진입(취소), 본인·시스템 관리자 강퇴 보호, 숨김 QA 관리자의 연락처 차단도 확인했다.

스크린샷 24개와 vCard 2개를 저장했으며 리더가 대표 데스크톱/모바일 메뉴 이미지와 실제 vCard 내용을 직접 읽었다. 테스트·빌드 당시 소스 해시 5개가 현재 소스와 일치한다. 추가 제품 수정·브라우저 재실행은 하지 않았으며 검증 서버 포트 3133은 종료했다. 브라우저 결과는 실제 전화 앱·주소록 저장·운영 RLS 동작을 검증한 것으로 해석하지 않는다.

## 독립 최종 리뷰

별도 컨텍스트 검토자가 원로그·실제 vCard·대표 화면과 최종 제품 소스를 대조해 웹 판정을 ship으로 기록했다. MC-01 관리 자격 분리 회귀를 검증했고 검토 범위에서 미해결 중요 기능 결함을 발견하지 않았다. 상세 근거와 제한은 member-card-actions-review.md를 따른다. 모바일은 prepared 상태로 유지한다.
