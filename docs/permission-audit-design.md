# 운영진 권한 정비 설계

## 권한 모델

기존 officer_permissions를 직책별 서비스 권한의 기준으로 유지한다. 모든 운영진에 members, fees, notices, events, feedback, elections, polls, surveys, welcome 관리 권한을 초기 적용한다. 이후 시스템 관리자가 같은 설정 화면에서 직책별 허용을 제외할 수 있다. 설정한 제외는 재조회·배포 시 자동 복구하지 않는다.

roles.manage와 권한 설정은 활성 시스템 관리자 전용이다. 회장의 officers.manage 위임을 제거하고 UI와 DB 배치 RPC에서 동일하게 검사한다. 정·부 담당·개인 예외 테이블은 만들지 않는다.

## 보안 경계

- 일반 회원 관리자: 일반 회원 등록·기본정보 편집·일반 회원 계정 발급/초기화 허용.
- 시스템 관리자: 운영진·시스템 관리자 계정 발급/초기화, 특권 지위 부여, 인증 계정 연결 변경, 권한 설정 허용.
- profiles 보호는 INSERT/UPDATE/DELETE를 모두 검증하며 시스템 관리자 대상 변경·삭제를 제한한다.
- 정상 Auth 생성 트리거와 service_role 내부 연결은 신뢰된 DB 실행자 기준으로 유지한다. JWT 부재만으로 허용하지 않는다.
- 자기 접근 제거와 마지막 로그인 가능한 활성 관리자 제거를 막는다.

## 서비스 독립성

회비·출석·팀 편성이 다른 서비스 권한을 요구하지 않도록 최소 필드 조회를 사용한다. 제한된 private 함수에 해당 서비스 권한, 로그인·활동 상태, 테스트 계정 제외, 고정 search_path를 적용한다. profiles의 개인정보 조회 RLS를 넓히지 않는다.

## 클라이언트

보호 필드는 편집 권한이 없으면 요청에 넣지 않는다. 관리자/운영진 계정 발급 버튼은 서버와 같은 대상 규칙으로 제한한다. 참여 종류별 권한 검사와 변경 건수 확인을 보완한다. 관리 화면 진입·포커스 복귀·권한 오류 뒤 서버 권한을 갱신하고 권한 상실 시 편집 및 관리 데이터를 정리한다. 기존 데이터 갱신 조정기를 재사용하여 병렬 요청이나 초기 요청 수를 늘리지 않는다.

모바일에 welcome.manage 설정을 포함한다. 웰컴 콘텐츠 편집을 새로 구현하는 것은 이번 권한 정비 범위에서 제외하며 기존 웹 운영 화면을 유지한다.

## 검증·배포

합성 프로필을 사용한 격리 PostgreSQL에서 기존 취약 경로와 업무 실패를 재현하고 수정 후 차단·정상 흐름을 검사한다. Edge Function은 mock Auth Admin API 호출 횟수로 거절이 변경 전에 발생하는지 검사한다. 웹·앱 테스트, lint/typecheck, production build와 독립 보안 리뷰 후 서버 발급용 app_metadata 표식을 보내는 Edge를 먼저 반영하고, 이를 검증하는 Auth 연결 트리거를 포함한 DB와 클라이언트를 순서대로 반영한다. 실제 회원의 회비·계정 초기화를 테스트로 실행하지 않는다.
인증 서비스의 사용자 INSERT 시점에는 서버 app_metadata가 아직 없을 수 있으므로 INSERT에서는 표식 없는 계정을 연결하지 않는다. 후속 app_metadata UPDATE에서 서버 발급 대상 UUID와 요청 대상·전화번호가 일치할 때만 연결한다. 사용자 수정 가능 user_metadata만으로 관리자 계정에 연결할 수 없게 하며 표식이 동일한 후속 수정에는 재연결하지 않는다. 기존 연결 계정은 변경하지 않는다.
