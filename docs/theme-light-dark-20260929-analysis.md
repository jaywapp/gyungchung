# 테마 라이트·다크 적용과 UX 즉시 항목 — 분석

- 요청 출처: jaywa-06 세션(사용자 요청 전달), 2026-09-29
- 근거 문서: 경충FC UX/UI 디자인 점검 보고서(Claude Docs), 테마 시안 캔버스
- 작업 브랜치: `feature/theme-light-dark`

## 목적

UX 점검 보고서의 즉시 항목 5건과 '매치데이' 테마의 라이트·다크 두 모드를 운영 코드에 반영한다.
테마 방향과 토큰 값은 보고서와 시안 캔버스에서 사용자가 이미 확정했다.
따라서 `CLAUDE.md`의 '콘셉트 3종 제시' 절차는 이번 작업에서 새로 수행하지 않는다.

## 현재 상태(코드 확인 결과)

| 항목 | 확인 내용 |
|---|---|
| 폰트 | `app/layout.tsx`는 Archivo(900)만 `next/font/google`으로 로드한다. `--font-sans` 첫 항목인 Pretendard Variable은 로드하지 않는다. |
| 한글에 Archivo | `globals.css`의 표시 폰트 묶음(`.eyebrow`, `.status`, `.schedule-head`, `footer` 등)이 12px·900·자간 .12em을 한글 라벨에도 적용한다. |
| 참여 마감 | `participation-hub.tsx`는 `form.status`만 보고 배지와 버튼을 정한다. `ends_at`이 지나도 DB 상태가 `open`이면 '진행 중'과 '참여하기'가 보인다. `formatDeadline`은 지난 마감에 '… 마감 · 마감'을 만든다. |
| 결과 공개 | `get_participation_results` RPC는 `status = 'closed'`, `show_results`, `ends_at <= now()`를 모두 만족해야 결과를 돌려준다. |
| 회원 강퇴 | `Members` 카드가 수정·강퇴 아이콘 버튼을 같은 모양으로 나란히 둔다. 확인 대화상자(`ConfirmDialog`)는 이미 있다. |
| 장소 링크 | `/events` 카드의 `.event-card-schedule a`에 색 지정이 없어 브라우저 기본 파란색이 보인다. |
| 이름 불일치 | 메뉴는 '의견', `feedback-hub.tsx`의 페이지 제목은 '사용자 제보'다. |
| 색 체계 | 토큰은 `:root`에 모여 있으나 `--navy`를 글자색·배경색 양쪽에 쓰고, `color-scheme: light`로 라이트만 가정한다. `var(--danger)`는 정의되지 않은 채 참조된다. |
| 그림자·강조선 | `--shadow-block`(7px 오프셋)과 버튼 오프셋 그림자, 카드 상단 `--accent-bar`(5px)가 반복된다. 모서리는 대부분 0이다. |

## 범위

포함
1. Pretendard Variable 실제 로드
2. Archivo는 영문 대문자 라벨·숫자만, 한글 라벨은 Pretendard 600·자간 0
3. 참여: 마감 판정(`status` 또는 `ends_at`), 배지·버튼·중복 문구, 마감 카드 흐림
4. 회원 카드: 강퇴를 '⋯' 메뉴로 이동, 위험 색, 기존 확인 단계 유지
5. 장소 링크 브랜드 색, 페이지 제목 '의견'
6. 하드코딩 색의 변수화, 라이트·다크 토큰, `[data-theme="dark"]` 덮어쓰기
7. 시스템 기본값 + 프로필 메뉴의 라이트·다크·시스템 전환(localStorage)
8. 오프셋 블록 그림자·카드 상단 강조선 제거, 모서리 규칙 적용

제외(보고서 로드맵의 다른 단계)
- 홈 히어로 개편, 모바일 하단 탭 바, 회원 목록 재설계·이니셜 아바타
- 타이포 스케일 6단계 정리, 랭킹 공동 순위(T1), 빈 상태 컴포넌트 통일
- 인증·권한·비즈니스 로직, DB 스키마·데이터

## 사용자 시나리오

- 다크 모드 기기의 회원이 처음 방문하면 다크 테마로 보인다.
- 로그인 회원이 마이페이지에서 '라이트'를 고르면 다음 방문에도 라이트로 유지된다.
- 마감일이 지난 설문 카드는 '마감' 배지만 보이고 참여 버튼이 없다. 결과 공개로 닫힌 설문에는 '결과 보기'가 보인다.
- 운영진은 회원 카드에서 수정 버튼은 바로 누르고, 강퇴는 '⋯' 메뉴를 열고 확인 대화상자를 거쳐야 실행할 수 있다.

## 완료 기준

- `npm run lint`, `npm test`, `npm run build` 통과
- 로컬 dev 서버에서 라이트·다크 × 데스크톱·모바일(390px) 확인. 데이터를 바꾸는 버튼은 누르지 않는다.
- `document.fonts`에 Pretendard Variable이 등록되고 한글 라벨에 자간이 적용되지 않는다.

## 확인이 필요했던 점과 결정

| 질문 | 결정 | 근거 |
|---|---|---|
| 프로필 메뉴가 없는 비로그인 방문자의 전환 방법 | 비로그인은 시스템 설정을 따른다. 전환 UI는 로그인 후 여는 마이페이지에만 둔다. | 요청이 '프로필 메뉴'로 위치를 지정했다. 다른 위치 추가는 범위 밖이라 보고서에 후속 항목으로 남긴다. |
| DB 상태가 `open`인데 마감일이 지난 설문의 '결과 보기' | 표시하지 않는다. | RPC가 `status = 'closed'`일 때만 결과를 공개한다. 버튼을 띄우면 누를 때마다 오류가 난다. |
| Pretendard 로드 방식 | `pretendard` 패키지의 dynamic-subset CSS를 레이아웃에서 import해 Next가 woff2를 자체 호스팅하게 한다. | 전체 가변 폰트 woff2는 2.0MB다. dynamic-subset은 CSS 13KB(gzip)이고, 화면에 쓰인 글자 조각만 내려받는다. |
