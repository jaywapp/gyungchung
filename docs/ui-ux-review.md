## 0. 총평

기능의 폭은 이미 충분합니다. 출석, 회비, 공지, 일정, 용병, 팀 편성, 경기 기록, MOM 투표, 랭킹, 의견, 선거·투표·설문, 권한 매트릭스까지 — 동호회 운영에 필요한 것이 사실상 다 있습니다.

문제는 폭이 아니라 **위계와 완결성**입니다. 세 가지로 요약됩니다.

1. **위계** — 여덟 개 탭이 같은 무게로 놓여 있습니다. 이 앱의 주간 반복 과업은 하나입니다: "이번 주 나가?"에 답하기. 그 하나를 중심으로 화면을 재배치하면 나머지는 대부분 부수적으로 정리됩니다.
2. **완결성** — 데이터 모델에는 있는데 화면에 없는 것이 많습니다. `capacity`(정원), `ends_at`(투표 마감), `show_results`(결과 공개), `undecided`(응답 취소)가 모두 저장되지만 어디에도 렌더되지 않습니다. 투표는 하는데 **결과를 볼 수 없습니다.**
3. **운영진 부담** — 회비 20명 등록에 모달 20번, 설문 질문 10개에 저장 10번, 출석 체크는 회원 수만큼의 순차 요청입니다. 운영진 화면이 회원 화면보다 손이 많이 갑니다.

아래는 심각도 순입니다.

# 1부 · 회원 화면

## P0 — 지금 사용자가 잘못 판단할 수 있는 것

### P0-1. 샘플 데이터가 진짜 일정처럼 보입니다

```ts
const sampleEvents: Event[] = [{ id: "sample-event", title: "주말 정기 풋살",
  starts_at: nextSaturday, venue: "브라보 풋살장", address: "서울시 송파구", ... }];
const [events, setEvents] = useState<Event[]>(sampleEvents);
// loadData: if (loadedEvents.length) setEvents(loadedEvents);
```

DB에 일정이 없거나 로드에 실패하면 **샘플이 그대로 화면에 남습니다.** 현재 배포된 홈이 정확히 이 상태입니다 — "8월 15일 토 18:00 브라보 풋살장"은 코드에 하드코딩된 다음 토요일입니다. 회원이 이걸 보고 실제로 구장에 갈 수 있습니다.

공지도 같습니다. `sampleNotices`의 `created_at`이 `new Date()`라 **언제 접속해도 "오늘 올라온 공지"로 보입니다.**

- 샘플 제거하고 빈 상태(`schedule-empty`는 이미 구현돼 있습니다) 노출
- 로드 실패는 빈 상태가 아니라 "불러오지 못했습니다 · 다시 시도" 오류 상태로 구분
- 개발용 샘플이 필요하면 환경 플래그나 seed 스크립트로 분리

### P0-2. 어느 경로로 들어와도 홈이 먼저 그려집니다

```tsx
// app/[section]/page.tsx — 모든 섹션이 <Clubhouse /> 하나
const [tab, setTab] = useState<Tab>("home");
useEffect(() => { setTab(pathTabs.get(window.location.pathname) ?? "home"); }, []);
```

`/members`로 직접 들어오거나 새로고침하면 **홈 히어로가 한 프레임 렌더된 뒤** 회원 화면으로 바뀝니다. 카카오톡으로 `/events`를 공유하면 상대가 보는 첫 화면은 홈입니다. 서버가 내려주는 HTML도 홈 내용이라 `sectionMeta`의 메타데이터와 본문이 어긋납니다.

- 초기 `tab`을 서버가 받은 `params.section`으로 세팅, 최소한 `usePathname()`으로 첫 렌더부터 올바른 탭 렌더

### P0-3. `참석 예정 -명`은 사실 0명이라는 뜻입니다

```tsx
<span>참석 예정 <b>{goingCount || "-"}명</b></span>
<span><b>{memberCount}</b> ACTIVE MEMBERS</span>
```

`0 || "-"`이므로 **아무도 응답 안 한 상태와 로딩 중이 같은 기호**입니다. 비로그인 시 `attendance`가 빈 배열이라 항상 `-명`이고, `memberCount`도 0이라 첫 방문자에게 **"0 ACTIVE MEMBERS"**가 보입니다. 12년 된 팀이 회원 0명으로 보입니다.

- 로딩 중 스켈레톤 / 비로그인 시 공개 집계 노출 또는 블록 숨김 / 진짜 0은 "0명 · 첫 번째로 참석해 주세요"

### P0-4. Supabase 원문 오류가 그대로 노출됩니다

```ts
if (error) return showToast(error.message);      // clubhouse, feedback, participation
if (error) return window.alert(error.message);   // AdminEditor
```

`new row violates row-level security policy for table "attendance"` 같은 영문 메시지가 회원과 운영진 모두에게 그대로 나갑니다. 로그인 모달만 에러 코드를 한국어로 매핑해 두었고(`invalid_credentials`, `weak_password` …), 나머지 경로에는 그 처리가 없습니다. 운영진 편집기는 아예 **브라우저 기본 `alert`**입니다.

- 공통 `toErrorMessage(error)`로 통일, 원문은 콘솔에만
- 성공/오류 토스트를 시각적으로 구분 (현재 둘 다 `<Check>` 아이콘)
- 토스트에 `role="status"`, 오류는 `role="alert"` — 현재 스크린리더에 전혀 읽히지 않습니다
- `window.alert` / `window.confirm` 제거하고 앱 모달로 통일

## P1 — 핵심 과업(RSVP)의 마찰

### P1-1. 로그인 후 원래 자리로 돌아오지 않습니다

```ts
callbackUrl.searchParams.set("next", `/?auth=${mode}`);
```

`/events`에서 "참석하기"를 눌러 로그인해도 **홈으로 떨어지고**, 하려던 동작도 사라집니다. 주간 반복 과업에서 이 왕복은 곧 이탈입니다.

- `next`에 현재 경로 + 의도(`intent=rsvp&event=<id>`)를 실어 복귀 후 자동 처리

### P1-2. 두 버튼의 상태가 어긋납니다

```tsx
<button>{user ? "참석" : "로그인 후 참석"}</button>
<button>불참</button>
```

한쪽만 로그인이 필요한 것처럼 보입니다(실제로는 둘 다 모달을 엽니다). 승인 대기 회원은 버튼이 **정상으로 보이는데** 누르면 토스트만 뜹니다.

- 비활성 사유는 누르기 전에: `disabled` + 사유 한 줄
- 로그인 필요 이유 명시: "참석자 명단에 이름이 남기 때문에 로그인이 필요합니다"

### P1-3. 응답을 취소할 수 없습니다

`Attendance["status"]`에 `undecided`가 있지만 **이 값을 만드는 UI가 없습니다.** 한 번 누르면 참석/불참 중 하나에 갇힙니다.

- 선택된 버튼 재클릭으로 해제(토글), 응답 후 카드를 `참석으로 응답함 · 변경` 상태로 치환

### P1-4. 마감이 없습니다

공지에는 "목요일 밤 10시까지"라고 적혀 있지만 시스템에 마감 개념이 없습니다. 홈 RSVP는 `isPast` 검사조차 없어 **경기 시작 시각이 지나도 참석 버튼이 눌립니다.** 일정 페이지는 `disabled={isPast}`로 막고 있어 두 화면 동작이 다릅니다.

- `rsvp_closes_at` 추가(없으면 `starts_at - 48h`), `응답 마감 목요일 22:00 · D-2` 표기, 마감 후 잠금
- 홈과 일정 페이지의 RSVP를 하나의 컴포넌트로 통일

### P1-5. `capacity`가 화면에 없습니다

`Event.capacity`(기본 18)는 편집기에서 입력받지만 **회원 화면 어디에도 렌더되지 않습니다.** 풋살은 인원이 성패를 가르는데 "지금 몇 명 중 몇 명"을 알 수 없습니다.

- `12 / 18명` + 진행 막대, 미달 시 "2명 더 필요합니다", 초과 시 대기 등록
- 참석자 이름을 칩으로 노출 — **누가 나오는지가 참석 결정의 가장 큰 변수**입니다. 데이터는 이미 다 있습니다

### P1-6. 일정 목록이 과거부터 시작합니다

```ts
supabase.from("events").select(…).order("starts_at")   // 오름차순, 필터·limit 없음
```

일정 탭을 열면 **가장 오래된 경기부터** 나오고 지난 일정도 전부 포함됩니다. 시즌이 쌓이면 다음 경기를 보려고 계속 스크롤해야 합니다.

- 기본은 "다가오는 일정", 지난 일정은 별도 탭 또는 접힌 아카이브(최신순), 페이지네이션

### P1-7. 일정 페이지에는 "불참"이 없습니다

홈은 참석/불참 2지 선다, 일정 페이지는 `참석하기` 단일 버튼입니다. 불참을 알리려면 홈으로 돌아가야 하고 그마저도 다음 일정 하나에만 가능합니다.

### P1-8. 용병 등록을 회원이 할 수 없습니다

`guest_players`, `event_guest_players`, `event_guest_fees`까지 모델은 완비돼 있지만 회원 화면에서는 **읽기 전용**입니다. 등록은 운영진 콘솔에서만 가능합니다. 실제로는 "이번 주에 친구 한 명 데려갈게"가 개인 단위로 발생합니다.

- 일정 카드에 "지인 데려오기" — 이름·포지션만 받고 등록자 기록, 취소 권한과 참여비 안내 동시 노출

## P2 — 데이터가 쌓이면 무너지는 곳

### P2-1. 회비 화면에 "내 회비"가 없습니다

```ts
supabase.from("fees").select("*, profiles(name)").order("month", { ascending: false })
```

전 회원 × 전 개월 납부 내역이 **한 장의 표**로 나옵니다. 20명 × 12개월이면 240행이고 검색·필터·정렬이 없습니다. 회원이 알고 싶은 건 한 줄입니다 — *"나 이번 달 냈나?"*

- 상단 개인 요약: `2026년 8월 · 미납 30,000원 · 납부 마감 8/10`
- 아래 내 이력, 전체 표는 운영진 뷰 또는 접힘
- 계좌번호 노출 + 탭 복사 — 회비의 실제 마찰은 "계좌번호 다시 찾기"에서 발생합니다
- 회비 정책(관리자 15,000 / 일반 30,000 / 참여 10,000)이 `PageIntro` 설명 문단에 묻혀 있습니다. 표나 카드로 분리

홈 회비 패널도 같습니다. `fees.find(f => f.member_id === user.id)`로 최근 한 건만 뽑는데 **몇 월 회비인지 표시가 없어** 금액만 덩그러니 남습니다.

### P2-2. 모든 데이터를 한 번에 불러옵니다

`loadData`는 인증 상태가 바뀔 때마다 **15개 쿼리를 병렬 실행**합니다 — 회원, 신청서, 회비, 용병 회비, 출석, 의견, 설문 응답, 권한 2종, 용병, 랭킹, MOM 3종. 홈만 보려는 사용자도 전부 기다립니다.

- 탭 진입 시점에 필요한 것만 로드, 로딩 스켈레톤 도입(현재는 샘플 → 실데이터 교체로 레이아웃이 튑니다)

### P2-3. 목록에 검색·필터가 전혀 없습니다

회원, 회비, 공지, 일정, 의견, 운영 관리 전 탭에 없습니다. 지금은 데이터가 적어 안 보이지만 한 시즌이면 드러납니다.

### P2-4. 삭제가 `window.confirm`입니다

앱 전체가 커스텀 모달을 쓰는데 삭제만 브라우저 기본 대화상자이고, **삭제 대상의 이름도 보여주지 않습니다.**

- 확인 모달에 대상 명시, 또는 토스트에 5초 "실행 취소"

# 2부 · 의견 (`feedback-hub.tsx`)

### F-1. 공개 GitHub 등록이 체크박스 하나입니다

```tsx
<label className="check github-consent">
  <input type="checkbox" name="publish_to_github" /> 공개 GitHub 이슈로도 등록
</label>
```

체크 한 번으로 **제목과 본문이 공개 저장소에 영구 게시**됩니다. 되돌리는 UI는 없습니다. 되돌릴 수 없는 공개 행위치고 마찰이 너무 낮습니다.

- 제출 시 "공개 저장소에 게시됩니다" 확인 단계 + 게시될 내용 미리보기
- 게시 후 회수(이슈 닫기·삭제 요청) 경로 제공
- 안내 문구(`github-notice`)는 체크박스 **위**로 — 지금은 체크한 뒤에 읽는 순서입니다

### F-2. 익명 선택의 효과를 확인할 수 없습니다

회원 화면의 접수 카드는 애초에 작성자를 표시하지 않습니다. 그래서 `is_anonymous`를 켜든 끄든 **회원 눈에는 아무 차이가 없습니다.** 실제 차이는 운영진 목록(`익명 · 제목` vs `회원 · 제목`)에만 나타납니다.

- 누가 무엇을 보는지 명시: "운영진에게 이름이 보이지 않습니다 / 보입니다"
- 익명 제보에도 시스템은 작성자를 저장한다는 사실은 이미 안내하고 있습니다. 이건 잘 되어 있습니다

### F-3. 다 쓰고 나서야 못 낸다는 걸 압니다

제출 버튼만 `disabled={!user}`이고 입력 필드는 전부 열려 있습니다. 승인 대기 회원은 5,000자를 쓴 뒤 제출 시점에야 토스트로 거절당합니다.

- 로그인·승인 필요 상태에서는 폼 전체를 잠그고 사유를 상단에 표시
- 임시 저장(localStorage)으로 실패 시 내용 보존

### F-4. 답변을 받아도 알 수 없습니다

`officer_response`가 달려도 **알림이 없습니다.** 회원이 의견 탭을 다시 열어야 발견합니다. 미확인 표시도 없습니다.

- 내비 배지 또는 홈 패널에 "운영진 답변 1건", 상태 변경 시 알림

### F-5. 자잘한 것

- 접수 내역에 상태·분류 필터가 없습니다. 운영진은 전체 의견을 보게 되는데 헤딩은 `MY REPORTS · 접수 내역`으로 고정입니다
- 제목 120자 / 본문 5,000자 제한에 **글자 수 카운터가 없습니다**
- 작성자가 자기 글을 수정·삭제할 수 없습니다(운영진만 가능)
- GitHub 연결 실패 원인이 전달되지 않습니다 — `if (error || !data?.issueUrl) return false`로 삼켜집니다

# 3부 · 투표·설문 (`participation-hub.tsx`)

### V-1. 결과를 볼 수 없습니다 — 가장 큰 공백

`ParticipationForm.show_results`가 모델에 있고 편집기에서 "종료 후 결과 공개" 체크박스까지 제공하지만, **결과를 렌더하는 화면이 존재하지 않습니다.** 회장단 선거를 하고도 회원은 앱에서 당선자를 확인할 수 없습니다. 투표 참여의 보상이 없으면 다음 투표율이 떨어집니다.

- 마감된 항목에 "결과 보기" — 문항별 집계, 총 참여자 수, 참여율
- 비밀 투표는 집계만, 일반 투표는 선택 분포
- 내가 낸 응답을 다시 볼 수 있는 경로도 함께

### V-2. 마감일이 카드에 없습니다

`starts_at` / `ends_at`이 저장되지만 카드에는 `진행 중` / `마감` 두 상태만 보입니다. **언제까지인지 알 수 없습니다.**

- `8/20(수) 23:59 마감 · D-3` 표기, 임박 시 강조

### V-3. 설문 중 실수로 닫으면 답변이 전부 사라집니다

```tsx
<div className="modal-backdrop" onClick={() => setActiveId(null)}>
```

배경을 클릭하면 **확인 없이 즉시 닫히고** `answers`가 초기화됩니다. 긴 서술형 문항을 작성 중이던 회원은 전부 잃습니다.

- 입력이 있으면 닫기 전에 확인, 또는 답변을 임시 보관
- 문항이 많은 설문은 모달이 아니라 단계형 페이지 + 진행률로

### V-4. 복수 선택 필수가 강제되지 않습니다

```tsx
{question.type === "multiple_choice" && … <input type="checkbox" … />}   // required 없음
```

단일 선택·서술형에는 `required`가 붙지만 복수 선택에는 없습니다. `is_required`가 true여도 **빈 채로 제출됩니다**(제출 시 필터링돼 그냥 누락).

- 제출 전 검증 + 미응답 문항으로 스크롤·강조

### V-5. 이름이 세 가지입니다

| 위치 | 표기 |
|---|---|
| 내비 | 참여 |
| 페이지 `h1` | 참여 |
| 라우트 메타데이터 | 투표·설문 |

특히 **"참여"는 "참석"과 혼동됩니다.** 히어로의 `팀 의사결정 참여` 버튼도 여기로 오는데 사용자는 출석 관련으로 읽을 가능성이 높습니다.

- `투표`로 통일하고 진행 중 항목 수 배지(`투표 ②`) — 방문 동기가 생깁니다

### V-6. 자잘한 것

- 마감된 항목이 목록에 영구히 남습니다. 진행 중 / 마감 섹션 분리 또는 아카이브
- 평점 문항이 숫자 1~5만 표시됩니다. 양끝 라벨("전혀 아니다 / 매우 그렇다") 필요
- 카드에 문항 수·예상 소요 시간이 없어 "지금 할지" 판단이 안 됩니다
- 닫기 버튼이 텍스트 `×`입니다. 다른 모달은 아이콘(`<X />`) — 시각·터치 영역 모두 불일치
- 중복 제출 판정이 `error.message.includes("duplicate")` 문자열 검사입니다

# 4부 · 운영 관리 (`admin-console.tsx`)

운영진 화면이 회원 화면보다 손이 많이 갑니다. 반복 업무 세 가지가 특히 무겁습니다.

### A-1. 가입 승인 대기가 눈에 띄지 않습니다

회원 목록은 이름 가나다순 단일 리스트입니다. 승인 대기자는 **전체 회원 사이에 섞여 있고**, 탭에 배지도 없고 필터도 없습니다. 가장 시간에 민감한 업무가 가장 찾기 어렵습니다.

- 승인 대기 건을 최상단 별도 블록으로 + `회원 관리 ③` 배지
- 신청서 정보를 목록에서 바로 펼쳐 보고 한 번에 승인

### A-2. 회비를 한 명씩 등록합니다

월회비 생성은 모달에서 회원 1명 → 월 1개 단위입니다. **20명이면 모달 20번**입니다. 매달 반복됩니다.

- "이번 달 회비 일괄 생성" — 대상 미리보기 후 한 번에 생성
- 목록에서 납부 상태를 인라인 토글(모달 없이)
- 미납자만 필터 + 독촉 문구 복사

또한 금액이 **수정 불가**입니다.

```ts
amount: standardFeeAmount   // 역할에서 자동 계산, 입력 필드 없음
```

부분 납부, 할인, 밀린 달 정산이 기록되지 않습니다. 결국 장부를 따로 쓰게 됩니다. 기본값은 자동 계산하되 수정은 열어두는 편이 안전합니다.

### A-3. 출석 체크가 회원 수만큼 요청을 보냅니다

```ts
for (const profile of activeProfiles) {
  if (…) ({ error } = await supabase.from("attendance").upsert({ … }));
  if (error) break;
}
```

순차 루프이고 **중간에 실패하면 앞부분만 저장된 채 멈춥니다.** 어디까지 저장됐는지 화면에 표시되지 않습니다. 팀 편성·경기 기록은 이미 RPC(`save_event_teams`, `save_competitive_event_stats`)로 원자적으로 처리하고 있으니 출석도 같은 방식이 맞습니다.

- 배치 RPC 한 번으로 저장
- 체크리스트를 "참석 예정 → 미응답 → 불참" 순으로 정렬 — 경기장에서 이름을 찾는 시간이 줄어듭니다
- 저장 중 진행 표시, 실패 시 어떤 회원이 반영 안 됐는지 명시

### A-4. 설문을 만들려면 질문 수만큼 저장해야 합니다

```tsx
<label>{row.id ? "새 질문 추가 (선택)" : "첫 질문"}<input name="prompt" … /></label>
```

편집기는 **한 번에 질문 하나만** 추가하고 끝에 덧붙입니다. 게다가 이미 등록된 질문이 편집기에 **표시되지 않습니다.** 수정·삭제·순서 변경도 불가능합니다. 10문항 설문 = 열고 닫기 10회, 그동안 무엇을 넣었는지는 기억에 의존합니다.

- 질문 목록을 편집기 안에 표시하고 인라인 추가·수정·삭제·드래그 정렬
- 공개 전 미리보기(회원에게 보이는 그대로)
- 선택지가 쉼표 구분 문자열이라 **쉼표가 들어간 보기를 만들 수 없습니다.** 항목별 입력 행으로

### A-5. 되돌릴 수 없는 동작에 확인이 없습니다

- **"팀 다시 나누기"** — 저장된 팀 편성을 확인 없이 즉시 덮어씁니다. 경기 기록을 입력한 뒤 잘못 누르면 배정이 사라집니다
- **권한 매트릭스** — 체크박스를 누르는 즉시 DB에 반영됩니다. 저장 버튼도 실행 취소도 없습니다. 잠긴 셀은 `disabled`일 뿐 **왜 잠겼는지 설명이 없습니다**
- **편집기 모달** — 배경 클릭 시 입력 내용이 확인 없이 사라집니다

### A-6. 관리자 화면에 영문 enum이 그대로 나옵니다

```tsx
meta={`${row.category} · ${row.status}`}                    // feedback → "operation · received"
meta={`${row.kind} · ${row.status}`}                        // forms   → "poll · open"
meta={`… · ${row.amount.toLocaleString()}원 · ${row.status}`} // fees    → "unpaid"
meta={`… · ${row.status}`}                                   // members → "active"
```

`categoryLabels`, `statusLabels`, `kindMeta` 같은 한국어 라벨 맵이 다른 컴포넌트에는 이미 있는데 여기서는 재사용하지 않습니다. 공통 모듈로 빼서 전 화면에서 같은 단어를 쓰는 게 맞습니다.

### A-7. 자잘한 것

- 10개 관리 탭 어디에도 검색·필터·페이지네이션이 없습니다. 회비 탭은 회원 회비 + 용병 회비를 한 목록에 섞고, 용병 회비 행에는 삭제가 없습니다
- 모든 편집기 제목이 `정보 수정` / `새 항목 등록` 하나입니다. 무엇을 편집 중인지 제목만으로는 알 수 없습니다
- 커피 내기 기록에서 팀 스코어와 개인 골 합계가 어긋나도 그대로 저장됩니다. 저장 전 경고 한 줄이면 충분합니다
- 팀 편성 대상(참석 예정 + 실제 출석 + 지정 용병)을 **생성 전에 미리 볼 수 없습니다.** 노쇼 한 명을 빼려면 출석 데이터를 고쳐야 합니다
- `secret_ballot`은 생성 시에만 설정 가능하고 수정 화면에는 표시조차 안 됩니다

# 5부 · 정보구조 · 시각 · 접근성

### S-1. 8개 탭이 모두 같은 위계입니다

`홈 / 회원 / 회비 / 공지 / 일정 / 랭킹 / 의견 / 참여` (+ 운영진 `관리`). 주간 사용 빈도는 일정·회비·공지에 몰려 있습니다.

- 1차: `일정 · 회비 · 공지` / 2차: `회원 · 랭킹 · 투표 · 건의함`을 더보기나 내 프로필 아래로
- 모바일은 하단 탭바(일정 / 회비 / 공지 / 내 정보), RSVP는 스크롤을 따라오는 하단 고정 바

### S-2. 내비 라벨과 페이지 제목이 다릅니다

| 내비 | 페이지 제목 |
|---|---|
| 참여 | 참여 / 투표·설문 (메타데이터) |
| 의견 | 사용자 의견 |
| 랭킹 | 활동 랭킹 |

### S-3. 같은 일정이 홈에 두 번 나옵니다

히어로 우측 `schedule-card`와 클럽하우스 `rsvp-panel`이 날짜·시간·장소·지도 링크를 그대로 반복합니다. 한 화면 안의 반복은 강조가 아니라 스크롤 비용입니다. 상단 카드에 RSVP를 직접 넣고 아래 패널을 없애는 편이 낫습니다.

### S-4. 날짜가 절대값뿐입니다

`formatDate → "2026년 8월 15일 토"`. 사용자가 매번 오늘과 비교 계산해야 합니다.

- `이번 주 토요일 · 8/15 18:00 (D-4)` 병기
- 캘린더 추가(.ics / Google Calendar) — 동호회 앱에서 체감 효용이 가장 큰 기능 중 하나입니다

### S-5. 지도 링크가 검색 쿼리입니다

```ts
`https://map.naver.com/p/search/${encodeURIComponent("브라보 풋살장 서울시 송파구")}`
```

동명 구장이 여러 개면 잘못된 지점으로 갑니다. `address`도 "서울시 송파구" 수준이라 정밀도가 낮습니다. 좌표나 네이버 place ID 저장 + 모바일 지도 앱 스킴 연결을 권합니다.

### S-6. MOM 투표가 조용히 사라집니다

```ts
const canVote = Boolean(user && profile?.status === "active" && isPast &&
  attendance.some(row => … && row.checked_in_at));
```

운영진이 체크인을 찍지 않으면 투표 버튼이 **아무 설명 없이 나타나지 않습니다.** 참석했는데 투표를 못 하는 회원은 이유를 알 수 없습니다. 조건 미충족 사유("출석 확인이 등록되면 열립니다")와 투표 마감 기한을 함께 표시해야 합니다.

### S-7. 신규 회원의 관문이 4단계입니다

`회원가입 → 이메일 인증 → (소셜은) 이메일 등록 → 가입 신청서 → 관리자 승인 대기`

각 단계는 합리적이지만 누적되면 깁니다. 신청서 항목도 적지 않습니다 — 이름, 전화번호, **생년월일**, 거주지역, 선호 포지션.

- 생년월일의 용도를 밝히거나 선택 항목으로
- 진행 표시("2/3 단계")로 끝이 보이게
- 승인 대기 중에도 **공지와 일정은 읽을 수 있게** — 지금은 배너만 뜨고 할 수 있는 게 없습니다
- 승인 배너가 모든 탭 상단에 항상 고정 노출됩니다. 닫기 또는 축약 제공

### S-8. 영문 오버라인이 전 섹션에 반복됩니다

`NEXT SCHEDULE`, `WEEKEND FUTSAL`, `MEMBER LOCKER ROOM`, `LATEST NOTICE`, `MEMBERSHIP FEE`, `SQUAD`, `NOTICE BOARD`, `CLUB RANKING`, `MOM HALL OF FAME`, `MEMBER VOICE`, `TEAM DECISIONS`, `OPERATIONS DESK`, `ADMIN EDITOR`, `MEMBER ACCESS`… 모든 `PageIntro`와 패널이 같은 패턴입니다. 반복되면 강조는 사라지고 장식만 남습니다. 홈 2~3곳에만 남기는 것으로 충분합니다.

### S-9. 헤더에 "확인 중" 텍스트가 노출됩니다

```tsx
{authLoading ? <span className="auth-loading">확인 중</span> : …}
```

내부 상태가 그대로 UI에 드러납니다. 스켈레톤 또는 비활성 버튼이 자연스럽습니다.

### S-10. 접근성 — 잔여 항목

이미 잘 되어 있는 부분이 많습니다: 아이콘 버튼 `aria-label`, 표 `<caption class="sr-only">`, `aria-current`, Escape로 메뉴 닫기, 폼 오류 `role="alert"`, 권한 매트릭스 체크박스 라벨. 남은 것:

- **토스트에 라이브 리전이 없습니다** — 저장·삭제·오류 결과가 스크린리더에 전달되지 않습니다
- **모달 포커스 트랩이 없습니다** — 로그인, 관리자 편집기, MOM 투표, 설문 응답 전부 Tab이 배경으로 빠집니다. 로그인 모달은 Escape 닫기도 없습니다
- **히어로의 큰 날짜 숫자(`giant-number`)가 중복 낭독**됩니다. `aria-hidden="true"` 필요
- `event.note`가 라벨 없는 `<span>`으로 출력됩니다 — "흰색·검정색 유니폼을 모두 챙겨주세요"가 무슨 정보인지 맥락이 없습니다
- 모바일 메뉴 오버레이에 `role="dialog"` / `aria-modal` 없음
- 어두운 배경 위 `eyebrow`·보조 문구의 대비비 4.5:1 확인
