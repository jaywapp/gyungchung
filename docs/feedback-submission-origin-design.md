# 제보 접수 경로 기록 설계

## 데이터 계약

`public.feedback.submission_source`는 nullable `text`이고 허용값은 `web`, `app`이다. 기본값과 과거 데이터 보정은 두지 않는다. `NULL`은 미확인을 뜻한다. 제보 내용의 분류, 작성자 권한, 공개 동의와 무관한 참고 메타데이터다.

웹과 앱의 기존 INSERT payload에 각각 고정값 하나만 더한다. 기존 양식, 운영진 편집, 회원 공개 피드, 공개 GitHub 이슈의 본문과 발행 조건은 바꾸지 않는다. 클라이언트 `Feedback` 타입에는 이전 행과 API 계약을 감안해 선택적 nullable 필드를 둔다.

## 배포 순서와 보안

서버 마이그레이션을 먼저 적용하고 DB 기본값 부재·허용값·이전 payload 호환을 검증한다. 그다음 웹과 앱 클라이언트를 배포한다. `feedback`의 기존 RLS 및 권한을 재정의하지 않고, `feedback_feed`에 새 필드를 추가하지 않는다. 출처는 클라이언트가 기록한 유입 경로이므로 권한 판단이나 신뢰할 수 있는 분류 근거로 사용하지 않는다.
