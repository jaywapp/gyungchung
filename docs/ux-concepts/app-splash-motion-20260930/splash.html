앱을 열 때 보이는 첫 1초

세 시안 모두 운영체제가 먼저 띄우는 정지 화면(첫 프레임)에서 시작해, 같은 그림 위에서 움직임을 이어 붙이고 로그인 홈으로 넘어갑니다. 웹앱(PWA)과 Expo 앱이 같은 타이밍 값을 씁니다. 휴대폰 화면 안의 홈은 예시입니다.

기기에 '움직임 줄이기'가 켜져 있어 완성 화면만 보여 줍니다. 앱에서도 같은 방식으로 동작합니다.
A

킥오프 궤적

1.8 s · 선택됨

웹 첫 화면의 궤적 드로잉을 줄인 버전입니다. 공이 날아와 'GCFC' 밑을 굴러가며 글자를 띄우고, 마침표 자리에 멈춥니다. GC는 채운 글자, FC는 윤곽선으로 나눴습니다.

  1. 0 ms정지 화면: 남색 바탕에 하프라인과 센터서클
  2. 150페널티 마크에서 공을 차 올림
  3. 630착지 후 굴러가며 'G·C·F·C'가 차례로 떠오름
  4. 1270공이 마침표로 멈추고 클럽 문구가 펼쳐짐 → 페이드로 홈 공개

어울리는 경우 웹과 앱의 인상을 하나로 묶고 싶을 때. 길어서 두 번째 실행부터는 C처럼 짧은 버전으로 바꾸는 것을 권합니다.

B

골망 흔들기

1.3 s · 모든 실행

아래에서 찬 공이 골망에 꽂히고, 망이 출렁인 자리에서 GC 엠블럼이 튀어나옵니다. 엠블럼은 그대로 홈 상단 로고 자리로 날아가 앉습니다.

  1. 0 ms정지 화면: 남색 바탕에 골대와 그물
  2. 120화면 아래에서 슈팅, 공이 멀어지며 작아짐
  3. 440그물 출렁임 → 엠블럼과 '경충FC' 등장
  4. 1000엠블럼이 상단 로고로 이동하며 홈 공개

어울리는 경우 '경기하러 들어간다'는 기대감을 주고 싶을 때. 득점 장면이라 가장 힘이 있고, 로고로 이어져 끊김이 없습니다.

C

코트 펼치기

0.8 s · 모든 실행

엠블럼 테두리가 화면 가득 코트 라인으로 펼쳐지고, 남색 바탕이 로고 자리로 빨려 들어가며 홈이 드러납니다. 공은 등장하지 않습니다.

  1. 0 ms정지 화면: 남색 바탕에 GC 엠블럼
  2. 100엠블럼 테두리가 코트 라인으로 펼쳐짐
  3. 300남색 바탕이 상단 로고 자리로 모이며 홈이 드러남
  4. 780엠블럼이 로고에 겹쳐지며 종료

어울리는 경우 매번 여는 앱이라 기다림을 줄이고 싶을 때. 가장 짧고 조용하며, 데이터가 늦게 와도 부담이 없습니다.

공통 구현

웹앱과 Expo 앱에 같은 모션을 넣는 방법

웹앱(PWA)Expo 앱(iOS·Android)
정지 화면manifest의 남색 배경과 아이콘으로 브라우저가 자동 생성. iOS는 apple-touch-startup-image를 기기 크기별로 준비. 지금은 manifest가 없어 먼저 추가해야 합니다.expo-splash-screen 설정에 첫 프레임 이미지와 남색 배경 지정. 다크 모드도 같은 남색이라 이미지 하나로 충분합니다.
모션홈 화면 앱으로 실행됐을 때만(display-mode: standalone) 첫 화면 위에 SVG와 Web Animations API로 재생. 히어로 모션과 같은 방식입니다.정지 화면을 preventAutoHideAsync로 붙잡아 둔 채 같은 그림을 그린 뒤 숨기고, react-native-reanimated와 react-native-svg로 재생.
공유좌표와 타이밍(ms)을 공용 모듈 하나에 두고 두 플랫폼이 가져다 씁니다. Lottie 파일은 만들지 않습니다(디자인 도구 없이 코드로 관리하고, 테마 토큰을 그대로 쓰기 위해).
  • 첫 프레임은 정지 화면과 픽셀 단위로 같게 맞춰 넘어가는 순간이 튀지 않게 합니다.
  • 화면을 탭하면 바로 건너뜁니다. 움직임 줄이기 설정에서는 재생하지 않습니다.
  • 스플래시는 로딩을 기다리는 데 쓰지 않습니다. 모션이 끝났는데 데이터가 없으면 홈의 기존 스켈레톤을 보여 줍니다.
  • 브라우저 탭에서 여는 일반 웹 방문에는 재생하지 않습니다. 방문자 홈에는 이미 히어로 모션이 있습니다.
