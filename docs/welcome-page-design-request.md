# 경충FC 웰컴 페이지 시안 제작 요청서

- 작성일: 2026-10-02
- 상태: 시안 제작 완료, 03 구단 소개형 선택(2026-10-02). 산출물은 [시안 README](ux-concepts/welcome-page/README.md)
- 대상: `gyungchung` 웹의 공개 `/welcome` 및 기존 관리자 내 웰컴 페이지 편집 화면
- 관련 문서: [분석](welcome-page-analysis.md), [설계](welcome-page-design.md), [작업 계획](welcome-page-tasks.md)

## 구현 단계의 최종 정정 (2026-10-02)

사용자가 03 구단 소개형과 관리 공통안을 선택하고 구현을 요청했다. 앱 설치는 필수이며, 신규 회원이 간단히 이해하도록 회칙은 공개 페이지·관리 편집·콘텐츠 구조에서 모두 제외했다. 최종 흐름은 환영 → 운영진 소개 → 앱 설치·계정 안내다. 초기 관리 권한은 회장·시스템 관리자, 검색 노출은 제외한다.

아래는 시안 제작 당시의 요청을 보존한 기록이다. 회칙·선택 설치에 관한 초기 내용은 제품에 적용하지 않는다. 최신 제품 기준은 [요구사항](welcome-page-analysis.md)과 [설계](welcome-page-design.md)를 따른다.

## 전달 목적과 이번 단계

다음 단계에서 디자이너 또는 디자인 AI가 이 문서를 바탕으로 공개 페이지 시안 3종과 관리자 공통안 1종을 제작하도록 요청합니다. 이 문서 작성 자체는 시안 제작, 운영 코드 구현, 배포 또는 운영 데이터 변경을 포함하지 않습니다. 작성 시점에는 선택된 시안이 없었고, 이후 공개 시안 3종을 비교해 사용자가 03 구단 소개형을 선택했습니다.

디자인 해석: 처음 방문한 사람과 기존 회원이 경충FC의 회칙과 운영진을 이해하고 Android 앱 설치 또는 웹 이용을 시작하는, 기존 GCFC 브랜드 안의 안내 페이지입니다. 공개 화면은 행동을 돕는 안내와 회칙 읽기, 관리자 화면은 반복 편집 업무의 정확성을 우선합니다.

## 이용자와 성공 기준

- 처음 방문한 사람: 로그인 없이 회칙과 공개 운영진 소개를 읽고 APK를 다운로드합니다.
- 기존 회원: 앱을 설치하거나 웹으로 이동하고, 계정 이용 방법을 확인합니다.
- 운영진: 초안을 저장하고 미리보기한 뒤 게시하며, 공개 내용과 현재 초안을 구분합니다.
- 첫 화면에서 페이지 목적과 Android 다운로드 행동이 명확해야 합니다. 회칙과 운영진도 짧은 탐색으로 찾을 수 있어야 합니다.
- 페이지는 앱 설치를 강제하지 않습니다. “웹으로 이용하기” 경로를 함께 제공합니다.

## 모든 시안에 사용할 공통 콘텐츠

| 영역 | 필수 내용과 초기 카피 |
| --- | --- |
| 첫 안내 | “경충FC에 오신 것을 환영합니다” / “회칙과 운영진을 확인하고 앱으로 함께 시작하세요” |
| 주요 행동 | “Android 앱 다운로드”, “회칙 보기”, “웹으로 이용하기” |
| 회칙 | 제목, 목차, 본문, 선택적인 시행일·개정일. 긴 조항을 읽고 다시 위치를 찾을 수 있는 구조 |
| 운영진 | 공개 이름, 직책, 소개. 사진은 선택 사항이며 사진 없는 구성도 완결되게 제시 |
| Android | 설치 버튼, 버전·파일 크기 정보, 설치 방법, 계정 이용 안내 |
| iOS | 기본 카피 “iOS 앱 출시 준비 중”. 실제 주소가 승인되기 전에는 다운로드 버튼 비활성 |
| 계정 안내 | “계정 등록은 운영진에게 요청해 주세요. 안내받은 전화번호와 초기 비밀번호로 로그인한 뒤 새 비밀번호를 설정합니다.” |

실제 회칙과 운영진 명단은 아직 제공되지 않았습니다. 세 시안 모두 같은 예시 데이터를 사용하고, 회칙은 “시안용 예시 / 실제 회칙 아님”, 운영진 이름과 소개는 “시안용 예시”라고 영역 안에 명확히 표기합니다. 예시 이름은 “운영진 이름 예시”처럼 가상임이 드러나는 문구를 사용합니다. 창단 연도, 구단 실적, 실제 인물 사진, 연락처를 임의로 창작하지 않습니다. 전화번호·이메일·내부 회원 명단은 공개하지 않습니다. 가입 버튼이나 공개 회원가입 폼을 만들지 않습니다.

## 브랜드와 실제 자산

현행 웹 [globals.css](../app/globals.css), [layout.tsx](../app/layout.tsx)와 자산을 대표 기준으로 삼습니다. 새 페이지는 브랜드 확장이며 리브랜딩이 아닙니다.

- 배경 `#F6F7F4`, 네이비 `#0B1F33`, 브랜드 그린 `#157A43`, 강조 라임 `#B8F27C`를 기준으로 사용합니다. 라임 위 글자는 네이비이며 대비를 검증합니다.
- 한글은 Pretendard, 영문 표시용은 Archivo를 승계합니다. Archivo를 한글 본문에 억지로 적용하지 않습니다.
- 로고: [light SVG](../public/brand/gcfc-logo-horizontal-light.svg), [dark SVG](../public/brand/gcfc-logo-horizontal-dark.svg). 같은 이름의 PNG도 있습니다.
- 앱 아이콘: [app/icon.png](../app/icon.png). 자산 이름만으로 배경 적합성을 추측하지 말고 실제 렌더를 확인합니다.
- 현행 라이트/다크 테마의 토큰과 컨트롤 문법을 이어받고, 섹션마다 무관한 테마를 섞지 않습니다.
- 팀 사진이 제공되지 않으면 로고·타이포그래피 중심으로 구성합니다. 가짜 선수 사진이나 가짜 앱 스크린샷을 만들지 않습니다.

## 공개 페이지 시안 3종

같은 콘텐츠·브랜드·기능을 사용하면서 정보 구조, 타이포그래피 계층, 공간 배치, 모션 목적이 실질적으로 다른 세 안을 제시합니다. 색상만 바꾼 변형은 인정하지 않습니다. 아래는 출발점이며 더 적합한 구조를 자유롭게 제안할 수 있습니다.

| 출발점 | 구조적 질문 | 비교할 핵심 |
| --- | --- | --- |
| 안내 순서형 | 환영, 회칙, 운영진, 앱 시작을 차례대로 이해시키는가? | 읽기 흐름과 첫 설치의 연결 |
| 빠른 탐색형 | 다운로드와 회칙·운영진 바로가기로 목적별 방문을 돕는가? | 필요한 정보까지의 탐색 거리 |
| 구단 소개형 | 브랜드와 공개 운영진 소개로 소속감을 전달하며 행동으로 이어지는가? | 브랜드 인상과 안내 명확성 |

각 안은 한 문장 디자인 의도, 첫 화면의 초점, 모바일 읽기 순서, 회칙 탐색 방식, 모션의 이유, 장단점과 구현 부담을 설명합니다. 디자인 변수는 기본값을 복사하지 말고 이용자와 접근성을 근거로 정합니다. 모션은 등장 순서·탐색·상태 피드백에 쓰고, 반복 장식·스크롤 강제·필수 내용 지연을 피합니다. `prefers-reduced-motion`에서는 내용을 바로 표시합니다.

## 다운로드 동작과 상태

Android 첫 설치는 웹 로그인 없이 공개 APK로 직접 이동합니다. 앱 안의 업데이트 파일 요청에 회원 인증이 필요한 흐름과 구분합니다. 정상 상태 버튼은 표시한 버전정보와 동일한 선택 릴리스의 downloadUrl을 사용하고, 아래 고정 최신 주소는 버전정보 조회 실패 시 대체 경로로 사용합니다.

- 공개 최신 APK: https://github.com/jaywapp/gyungchung-releases/releases/latest/download/gyungchung-latest.apk
- 2026-10-02 확인 기준 최신 공개 배포: `android-v0.1.0-build.10`, 버전 `0.1.0`, 코드 `200010`, `85,611,780 bytes`(약 85.6 MB). 시안에서는 확인 날짜를 표시하고 영구 최신값으로 취급하지 않습니다.
- 버전정보는 기존 익명 metadata API가 검증한 최고 `versionCode`의 릴리스에서 읽는 계획입니다. 공개 릴리스 목록 첫 항목을 최신으로 간주하지 않습니다.
- metadata 응답의 `assetName`, `sizeBytes`, `notes`, `sha256`, `publishedAt`을 활용하고, 동일한 선택 릴리스의 `downloadUrl`을 추가하는 호환 확장을 제안합니다. 실제 계약 확정은 설계 문서를 따릅니다.
- metadata 실패 시 버전·크기를 숨기고 고정 공개 다운로드 링크를 유지합니다. 내부 오류나 API 명칭을 방문자에게 노출하지 않습니다.
- 설치 안내는 “APK를 내려받아 Android 기기에서 열고, 필요한 경우 이 출처의 설치를 허용하세요. 기존 앱이 있다면 삭제하지 않고 설치해 업데이트할 수 있습니다.”를 바탕으로 다듬습니다.
- iOS 상태는 `preparing`, `testflight`, `released`, `hidden`을 구분합니다. 승인된 실제 TestFlight/App Store 주소가 있을 때만 해당 행동을 활성화합니다. 주소가 없으면 가짜 버튼을 만들지 않습니다.
- 향후 iOS 배포가 GitHub의 전체 latest 선택에 영향을 줄 수 있으므로 플랫폼별 배포 선택 규칙은 구현 시 검증합니다.

## 관리자 공통안 1종

기존 관리자 콘솔의 “운영” 그룹 안에 “웰컴 페이지” 편집 메뉴를 추가하는 안을 제시합니다. 기존 관리자 UI를 승계하고 공개 페이지처럼 새 시각 체계를 만들지 않습니다. 접근은 계획된 `welcome.manage` 권한을 기준으로 합니다.

- 환영 문구·이용 시작 안내, 회칙, 공개 운영진 소개, 다운로드 표시와 iOS 상태를 편집합니다. Android 자동 버전정보는 읽기 전용으로 보여 줍니다.
- 공개 이름·직책·소개 편집은 계정의 회원 유형·실제 직책·시스템 권한 변경과 별개입니다.
- “초안 저장 → 미리보기 → 게시” 흐름을 보여 줍니다. 초안 수정 중에도 기존 게시본은 유지되며 게시 전 변경은 공개하지 않습니다.
- 게시본/초안 상태, 마지막 저장·게시 시점, 저장 성공, 저장·게시 실패, 동시 편집 충돌, 저장하지 않은 변경 이탈을 표현합니다.
- 실패 시 작성 내용을 유지하고 재시도를 안내합니다. 충돌 시 다른 변경을 덮어쓰지 않고 다시 불러와 비교하도록 안내합니다.
- 미리보기에는 초안임을 표시하고 실제 방문자가 보게 될 PC/모바일 표시를 확인할 수 있게 합니다.

## 반응형·접근성·예외 상태

- 모바일 360px·390px, 태블릿 768px, PC 1440px에서 확인합니다. PC와 모바일은 단순 축소 대신 각 폭에 맞는 순서와 밀도를 제시합니다.
- 라이트·다크 모두 확인하고 글자 확대 200%에서 본문·버튼·회칙 탐색·관리 입력이 잘리거나 겹치지 않게 합니다.
- 키보드로 모든 행동을 수행할 수 있게 하고 명확한 포커스, 의미 있는 제목 계층, 링크/버튼 구분, 사진 대체 텍스트를 제공합니다.
- 클릭 영역은 44px 이상, 가급적 48px로 구성합니다. 텍스트/컨트롤 대비는 WCAG AA를 검증합니다.
- 긴 회칙, 여러 문단, 긴 운영진 이름·직책, 운영진 0명/여러 명, 사진 없음, 회칙 미등록, 로딩/실패를 확인합니다. 더미 회칙은 짧은 정상본과 긴 검증본을 구분합니다.
- iOS 준비 중/테스트 참여/출시/숨김, Android metadata 실패를 별도 상태로 확인합니다. 기술 문제로 다른 공개 영역까지 숨기지 않습니다.

## 산출물과 선택 절차

- 공개 시안은 `docs/ux-concepts/welcome-page/concept-01/`, `concept-02/`, `concept-03/`에 각각 보관합니다.
- 각 폴더에 실행 가능한 HTML 또는 확인 가능한 프리뷰, 전체 페이지 PC/모바일 PNG, 의도·상태·접근성 확인 내용을 포함합니다.
- `docs/ux-concepts/welcome-page/README.md`에 세 안의 정보 구조·가독성·브랜드 인상·모션·접근성·구현 부담을 같은 기준으로 비교하고 실행 방법과 자산 출처를 적습니다.
- 관리자 공통안은 `docs/ux-concepts/welcome-page/admin/`에 기록하고 초안/게시/실패/충돌 상태를 최소 포함합니다.
- 데스크톱·모바일을 묶어 한 차례 검토하고 발견한 문제를 일괄 수정한 뒤 한 차례 재확인합니다. 실제 화면 제작에서는 impeccable과 design-taste-frontend의 해당 pre-flight를 적용합니다.
- 세 공개 시안의 비교 결과를 사용자에게 제시하고 선택·피드백을 분석/설계/작업 문서에 기록합니다. 선택 전에는 운영 코드·실데이터 연동을 시작하지 않습니다.
