# 운영 인증·DB 검증 분석

orchestrator: Codex

사용자가 남은 실제 인증·DB 연동 검증을 승인했다. 회원 데이터 훼손·실사용자 메시지 발송·비밀번호 변경 없이 진행한다. 기존 숨김 테스트 계정은 1개지만 사용 가능한 로그인 자격증명은 확인하지 못했다. 개발 DB branch는 없다. 운영 SQL은 개인정보 대신 참·거짓 집계만 반환한다.

실제 HTTP에서 Auth 설정·공개 공지 200, 무인증 사용자·회원 테이블·디렉터리·관리자 RPC·프로비저닝 401, 잘못된 전화번호 password grant 400, 잘못된 bearer 401을 확인했다. 공개 signup 설정은 비활성화되지 않았다. 가입을 실행하거나 설정을 변경하지 않았다.

운영 read-only transaction에서 숨김 테스트 관리자의 자기 프로필·목록 권한·숨김 처리 6항목을 확인했다. 미연결 인증 주체는 profiles/fees/feedback을 읽지 못하고 관리 권한·관리자 RPC도 거절되지만 get_member_directory는 회원 데이터 존재를 반환했다. 실제 이름·연락처는 출력하지 않았다.

기존 QA_RESPONSE_20260811.md는 디렉터리 대상을 로그인 회원으로 명시하며 profiles RLS와 분리된 제한 필드 RPC를 의도한다. 현재 함수는 auth.uid만 검사해 프로필 연결을 누락한다. 수정은 연결된 회원 여부만 추가한다. 승인 대기·비활성 프로필의 기존 조회 정책까지 확대 변경하지 않는다. 반환 필드·정렬·대상 활성 회원 필터·테스트 계정 제외는 유지한다.

운영 정책 적용은 최종 SQL과 권한 근거를 부모에게 전달해 리뷰한 뒤 진행한다. 비밀번호 로그인·실제 세션 갱신과 역할별 화면 E2E는 이번 SQL 검증으로 대체했다고 주장하지 않는다.
