# 주변 풋살장 프리셋 설계

## 데이터

- `public.venues`가 관리 원본이다. 구장 이름·주소·메모·기존 UUID 구조를 유지한다.
- 선택적 도시·안정적인 프리셋 키·출처 URL 목록·자료 확인 날짜·위경도를 추가한다. 기존 웹·앱의 명시적 조회 필드와 수동 등록은 호환된다.
- 원본 사실과 정제 목록은 저장소 `data/venue-presets/`에 보관한다. 불확실 후보와 중복 처리 근거는 조사 문서에 기록한다.
- 데이터 마이그레이션은 이름·주소와 확인된 별칭으로 기존 행을 연결한다. 기존 UUID·메모·생성자와 운영진이 이미 편집한 필드는 보존한다.
- 동일 프리셋 키의 재적용은 새로운 행을 만들지 않는다. 코트 ID를 이름·주소만으로 무조건 합치지 않는다.
- 기존 일정과 12주 자동 일정 설정의 장소 스냅샷을 일괄 변경하지 않는다.

## 일정 입력

기존 매치 콘솔의 폼과 색상·글꼴·선택 컨트롤을 유지하는 작은 기능 확장이다. 새로운 페이지나 주요 시각 디자인 교체를 하지 않는다.

등록·최근 사용 구장에 이름·주소 검색을 추가한다. 검색 결과가 없어도 바로 아래 직접 입력과 저장 옵션을 사용할 수 있다. 선택은 기존과 같이 `venue_id`·이름·주소를 채우고, 수동으로 이름이나 주소를 바꾸면 연결 ID를 해제한다.

검색이 일정 수정 값 자체를 바꾸지 않게 하고, 목록을 좁혀도 저장된 선택과 직접 입력은 유지한다. 폼의 네이티브 제출·뒤로가기·비활성 상태를 지킨다.

## 권한과 검증

기존 공개 구장 읽기와 `events.manage` 쓰기 RLS를 유지한다. 출처는 공개 사업장·시설 정보만 저장한다. DB 로컬 검증에서는 최초 적용·재적용·UUID 유지·수동 데이터 보존·역할별 읽기/쓰기·좌표/중복 제약을 확인한다. 운영에는 검증된 마이그레이션을 먼저 적용한 뒤 프론트를 배포한다.
