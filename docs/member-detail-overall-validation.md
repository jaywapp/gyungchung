# 회원 상세 오버롤 표시 검증

## 확인한 동작

회원 카드 선택 → 회원 상세 → 선택한 한 명의 능력치 RPC 조회 → 저장된 육각형 그래프·수치·평균 오버롤 표시. 기존 추가 능력치 진입 버튼은 제거했다.

- 회장·부회장·총무와 일반 회원 역할의 시스템 관리자가 상세 진입만으로 그래프를 확인한다.
- 회원 관리 권한 없이 능력치 권한만 있는 운영진도 같은 흐름을 사용한다.
- 일반 회원과 ratings.manage를 제외한 운영진은 상세 기본 정보를 볼 수 있지만 능력치 패널과 private 조회는 없다.
- 저장된 점수는 표시 상태로 시작하고 수정·취소가 가능하다. 미평가는 빈 입력 안내를 표시하며 저장 후 그래프와 오버롤이 반영된다.
- 목록만 열면 능력치 조회가 없고, 상세를 열면 선택한 회원 ID만 요청한다.
- 조회 오류는 미평가와 구분한다. 재시도 후 그래프가 복구되고 Escape와 카드 포커스 복원이 유지된다.
- 이전 회원의 늦은 응답은 현재 상세에 표시되지 않는다. 다시 열면 최신 점수를 읽고 권한 갱신으로 제외되면 패널이 사라진다.
- 전화걸기·연락처 저장 메뉴와 공개 팀 명단은 유지된다.

## 실행 결과

- 웹 테스트: 총 362개, 361개 통과·기존 skip 1개·실패 없음.
- TypeScript: noEmit·incremental false 검사 통과.
- 전체 lint: 오류 0, 기존 회원 메뉴 hooks 경고 2개 유지. 복사한 QA helper의 unused-variable 경고 1개는 수정하고 fixture·verify의 개별 lint 0으로 확인했다.
- 프로덕션 빌드: 정적 페이지 21/21 완료. 제품 코드 경고는 위 기존 hooks 2개다.
- 브라우저: 데스크톱 1440×1050, 모바일 390×844에서 18개 시나리오·213개 검사 통과. pageerror·예상 밖 외부 요청·공개 데이터 쓰기 모두 0.
- 스크린샷: 16개. 루트가 데스크톱·모바일의 직접 표시 그래프를 확인했으며 독립 리뷰에 제공했다.
- 브라우저의 실패 리소스 메시지는 의도적으로 발생시킨 합성 503 조회 오류다.

## 검증 한계와 산출물

기존 브라우저 커널 접근 제한으로 같은 세션에 기록된 headless Chromium 대체 경로를 사용했다. 합성 인증·REST·능력치 저장소만 사용하고 외부 요청과 WebSocket을 차단했다. 실제 운영 회원의 점수를 읽거나 수정하지 않았다.

이 변경은 기존 서버 RPC와 점수 패널을 재사용한다. DB 스키마·RLS·API 수정이 없어 DB 마이그레이션과 이전 DB 검증을 재실행하지 않았다. 모바일 앱 작업도 없다.

로컬 산출물은 .ux-review/member-detail-overall/의 test.log, type.log, lint.log, qa-lint.log, build.log와 browser/의 result.json·verify.log·16개 스크린샷이다. 앞선 .ux-review/member-overall/의 원본 증거는 보존했다.
