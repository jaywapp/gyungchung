# 총무 회비 저장 오류 수정 설계

`private.get_managed_fee_policy(uuid)`는 로그인 및 현재 `fees.manage`를 검증하고 숨김 계정을 제외한 대상 하나의 role/fee_plan만 읽는다. 내부 조회를 위한 definer는 비공개 스키마에 두며 고정 search_path, PUBLIC/anon/service_role 실행 철회와 authenticated 전용 실행을 적용한다. 공개 회비 트리거는 invoker를 유지한다.

트리거는 기존 직접 조회를 먼저 사용하고 대상이 RLS로 보이지 않을 때만 내부 조회를 사용한다. 따라서 본인·회원 관리자·서버 내부의 기존 동작을 유지한다. 회비 쓰기 RLS와 표준 금액/유형/중복 제약은 그대로다.

기존 `get_member_directory()`에 fee_plan을 추가한다. 본인 또는 회비 관리 권한이 있을 때만 값을 반환하고 다른 회원에게는 null을 반환한다. 기존 활동 회원·연결 계정·숨김 계정 필터와 기존 응답 필드는 유지한다. 웹/앱의 기존 객체 병합은 추가 필드를 수용하므로 새 조회나 앱 릴리스는 필요하지 않다.

격리 PostgreSQL에서 기존 총무 실패를 재현한 뒤 등록·수정·월회비/참여비·권한 회수·일반 회원/익명·비공개 정보·내부 자동 생성 계약을 검증한다. 운영 검증은 스키마·함수·권한과 읽기만 확인하며 실제 납부 기록은 만들거나 바꾸지 않는다.
