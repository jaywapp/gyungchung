# 경충FC 웰컴 페이지 설계안

공개 안내는 독립 경로로 제공하고, 편집은 기존 운영진 관리 화면에 통합한다. 공개용 콘텐츠만 저장하는 구조와 기존 APK 배포를 결합한다. 이 문서는 구현 기준 제안이며 데이터베이스나 제품 코드를 변경한 결과가 아니다.

- 작성일: 2026-10-02
- 상태: 시안 선택 및 미정 사항 확정 전
- 선행: [기획과 요구사항](welcome-page-analysis.md)
- 후속: [실행 계획](welcome-page-tasks.md), [시안 요청서](welcome-page-design-request.md)

## 페이지와 탐색

| 화면 | 진입 | 구성 |
| --- | --- | --- |
| 공개 웰컴 | /welcome | 환영·이용 안내·회칙·운영진·앱 다운로드 |
| 관리 편집 | 기존 /admin의 운영 그룹 → 웰컴 페이지 | 기본 안내·회칙·소개·앱 설정, 저장·미리보기·게시 |
| 초안 미리보기 | 관리 화면에서 권한 확인 후 진입 | 공개 렌더러를 재사용하되 초안 표시와 게시 상태 안내 |

공개 페이지는 app/welcome/page.tsx에 두어 회원용 Clubhouse 레이아웃과 데이터 로딩을 상속하지 않는다. 세션 유무·계정 상태와 관계없이 게시된 안내를 읽게 한다. 단일 페이지 안의 회칙·운영진·다운로드 앵커는 직접 공유할 수 있게 한다. 기존 루트 경로의 방문자·회원 경험은 유지한다.

공개 화면은 서버에서 게시본을 읽고 필요한 상호작용만 클라이언트에서 처리하는 안을 우선한다. 게시 데이터와 앱 버전 조회를 분리해 앱 조회가 늦거나 실패해도 안내 본문이 표시되게 한다. /welcome 전용 제목·설명·canonical·공유 이미지를 설정하고 검색 노출 결정에 따라 robots와 sitemap 포함 여부를 정한다.

## 공개 콘텐츠와 편집 기능

| 콘텐츠 | 저장 항목 | 입력·표시 원칙 |
| --- | --- | --- |
| 환영 | 제목·소개 | 짧고 구체적인 한국어, 과도한 글자 수 제한은 실제 자료로 조정 |
| 이용 안내 | 단계별 제목·본문 | 운영진 계정 등록, 전화번호 로그인, 최초 비밀번호 변경 |
| 회칙 | 제목·목차용 항목·본문·시행일·개정일 | 제목·문단·목록 중심 편집, 원문 의미 보존, 임의 HTML 실행 금지 |
| 운영진 | 공개 이름·직책명·소개·선택 사진·순서 | 회원 테이블 자동 공개 금지, 빈 사진 자리를 억지로 채우지 않음 |
| Android 안내 | 노출 여부·설치 안내 | 저장소·버전·체크섬·파일 크기는 배포 원본에서 조회 |
| iOS 안내 | 상태·문구·배포 링크 | preparing / testflight / released / hidden, 활성 상태는 HTTPS 링크 필수 |

작성 화면은 제목·목록 등 최소 서식을 제공한다. 초안 미리보기에도 운영 화면과 같은 본문 정제·렌더링 규칙을 적용한다. 실제 회칙에서 필요한 서식이 확인되기 전 범용 편집기나 HTML 입력을 도입하지 않는다.

사진 URL은 승인된 HTTPS 출처를 사용하고 파일 유형·크기·대체 텍스트 기준을 정한다. 직접 업로드를 후속으로 도입하면 초안 파일의 공개 여부, 교체·삭제, 저장소 접근 정책을 함께 설계한다.

## 초안과 게시본의 분리

한 페이지를 관리하므로 범용 CMS 대신 아래 두 저장 영역을 제안한다. 이름은 구현 시 프로젝트 규칙에 맞게 확정한다.

| 영역 | 내용 | 읽기·쓰기 범위 |
| --- | --- | --- |
| welcome_page_drafts | 편집 콘텐츠, revision, 수정자·수정 시각, 마지막 게시 기준 | 관리 권한 보유자만 |
| welcome_page_publications | 공개 콘텐츠, 게시 revision·시각 | 누구나 읽기, 게시 처리만 쓰기 |

공개 테이블에는 수정자 계정 ID·내부 회원 ID·초안·비공개 메모를 넣지 않는다. 회칙·운영진 배열 등 콘텐츠는 타입과 크기를 검증한 구조로 저장한다. 초기 버전에는 전체 변경 이력·복구 UI를 만들지 않고 수정·게시 감사 정보와 현재 초안을 보존한다.

1. 저장은 expected revision을 보내 다른 운영진의 변경을 덮어쓰지 않게 한다.
2. 미리보기는 권한을 확인해 초안을 읽는다. 공개 쿼리 옵션만으로 초안이 노출되지 않게 한다.
3. 게시는 현재 권한과 revision, 필수 콘텐츠·링크·배열 구조를 서버에서 다시 검증한다.
4. 한 트랜잭션으로 게시본을 교체하고 해당 초안의 게시 기준을 기록한다.
5. 성공한 뒤 공개 캐시를 갱신하고 결과를 읽어 확인한다. 실패하면 기존 게시본과 사용자의 입력을 유지한다.

최초 게시 전에는 공개 준비 안내를 제공한다. DB 오류를 빈 회칙이나 성공 상태로 처리하지 않는다. 게시본 조회 오류와 아직 게시하지 않은 상태는 구분한다.

## 편집 권한

welcome.manage 하나를 기존 직책별 권한에 추가하는 안이다. 초기 회장·시스템 관리자 허용은 제안이며 권한 적용 전에 확인한다. 기존의 활동 상태·연결 계정·위임 경계를 재사용한다.

UI 메뉴 조건뿐 아니라 권한 테이블의 허용 값, 배치 변경 RPC의 허용 목록, 시스템 관리자 권한 목록, 서버 저장·게시 검사, RLS와 GRANT를 함께 갱신해야 한다. profiles와 기존 회원 디렉터리의 공개 범위는 바꾸지 않는다.

비로그인과 일반 회원에게는 게시본 SELECT만 허용한다. 초안 SELECT와 INSERT/UPDATE 및 게시 실행은 관리 권한이 필요하다. 회칙·소개 편집과 계정 직책 설정은 별도 기능으로 유지한다.

## Android 배포 연동

기존 gyungchung-releases의 공개 파일을 사용한다. APK를 Vercel이나 새 Storage에 복제하지 않는다.

- 공유용 최신 주소: https://github.com/jaywapp/gyungchung-releases/releases/latest/download/gyungchung-latest.apk
- 메타데이터: 공개 릴리스의 update.json과 checksums.sha256
- 기존 서버: supabase/functions/mobile-updates, 공개 버전 GET과 인증된 앱 내 다운로드 분기
- 기존 선택 규칙: 완료된 정식 릴리스 중 검증을 통과한 가장 높은 versionCode

권장안은 기존 공개 메타데이터 응답에 검증한 동일 릴리스의 downloadUrl을 추가하는 호환 확장이다. 서버 내부에는 이미 검증된 assetUrl이 있으므로 이를 공개 배포 저장소의 주소로 제한해 전달한다. 기존 필드와 인증된 download=1의 계약을 유지하며, 설치된 앱이 추가 필드를 허용하는지 회귀 검증한다.

웹은 같은 응답의 versionName·versionCode·sizeBytes·notes·publishedAt와 downloadUrl을 함께 표시한다. GitHub 목록 첫 항목, 게시 시각, 문자열 버전 비교로 최신을 선택하지 않는다. 서로 다른 시점의 latest 파일과 버전 정보를 조합하지 않는다.

공개 메타데이터 확장이 불가능하면 웹 전용 서버 어댑터를 대안으로 검토하되 기존 검증·버전 선택 로직을 재사용한다. 일반 편집자가 임의 저장소나 임의 서버 URL을 지정하게 하지 않는다.

| 상태 | 방문자 표시 | 동작 |
| --- | --- | --- |
| 정상 | 버전·파일 크기·변경사항 | 같은 응답에서 선택한 APK로 이동 |
| 조회 중 | Android 다운로드와 확인 중 안내 | 본문은 즉시 읽기 가능 |
| 조회 실패 | 버전 수치 숨김, 설치 안내 유지 | 공개 최신 고정 주소와 재시도 제공 |
| 다운로드 영역 숨김 | Android 다운로드 항목 숨김 | 다른 안내 영역 유지 |
| 새 릴리스 공개 | 검증과 캐시 갱신 후 새 버전 표시 | 콘텐츠 재게시 불필요 |

기존 서버 캐시는 무토큰 600초, 선택 토큰 사용 시 120초다. 웹에서 장기 캐시를 중첩하지 않고 반영 지연을 운영진에게 설명한다. 조회 실패 때 이전 숫자를 최신 버전이라고 표시하지 않는다.

첫 설치는 공개 APK 링크를 사용한다. 회원 인증이 필요한 앱 내 스트리밍 경로를 웰컴 다운로드로 사용하거나 그 경로의 인증을 해제하지 않는다. 브라우저별 설치 허용 안내와 실패 시 외부 브라우저 열기 안내를 준비하고 최종 문구는 실제 Android에서 확인한다.

iOS는 TestFlight 또는 정식 배포 링크를 별도 필드로 관리한다. 공개 releases 저장소의 Android 채널을 유지하며, 향후 다른 플랫폼 파일을 같은 저장소에 올릴 때도 Android 최신 링크가 엉뚱한 플랫폼을 가리키지 않는지 검증한다.

## 화면 상태와 접근성

| 공개 페이지 | 관리 화면 |
| --- | --- |
| 처음 방문, 로그인 상태, 회칙이 긴 경우 | 초안 없음, 게시본 있음, 미게시 변경 있음 |
| 사진 없음, 소개·이름이 긴 경우 | 저장 중·성공·실패, 게시 중·성공·실패 |
| Android 정상·조회 실패 | 동시 수정 충돌, 권한 상실 |
| iOS 준비 중·테스트·정식 배포 | 미저장 이탈, 필수 콘텐츠 누락 |
| 게시 준비 중, 게시 데이터 조회 오류 | 권한 없는 직접 접근 |

모바일 360·390px, 태블릿 768px, 데스크톱 1440px에서 확인한다. 밝은·어두운 테마, 200% 글자 확대, 키보드 탐색, 포커스, 제목 구조, 색 대비와 움직임 줄이기를 포함한다. 다운로드와 회칙 목차가 고정 UI에 가려지지 않도록 한다.

## 검증과 적용 순서

1. 비로그인과 모든 회원 상태에서 게시본 열람 및 공개 APK 링크 접근을 확인한다.
2. 비로그인·일반 회원의 초안 읽기와 직접 API 쓰기·게시가 거절되는지 확인한다.
3. 제한 운영진의 허용·거절, 권한 회수 후 저장 거절, 소개 편집의 계정 권한 비변경을 확인한다.
4. 저장은 공개 페이지에 반영되지 않고 게시만 일관되게 반영되는지 확인한다.
5. 동시 편집, 게시 실패·재시도, 캐시 갱신과 재방문 시의 내용 일치를 확인한다.
6. metadata와 APK의 버전·크기·파일 주소 일치, 새 버전 전환·GitHub 장애·iOS 상태를 확인한다.
7. 기존 설치 앱의 업데이트 조회·인증된 다운로드와 기존 웹 회원 기능을 회귀 확인한다.
8. 변경 범위 검사, lint·타입·프로덕션 빌드, DB 권한 검사를 수행한다. DB 변경은 앱 배포 전에 검증한다.

현재 단계의 산출물은 문서다. 시안 선택 후 제품 구현을 진행하고 실제 배포는 해당 작업의 승인 범위와 저장소 규칙을 다시 확인한다.

## 구현 접점

- app/welcome/page.tsx: 새 공개 경로
- components/admin-console.tsx: 기존 운영 그룹과 권한 기반 메뉴 확장
- 공개 렌더러와 전용 관리 편집기: 새 컴포넌트로 나누어 미리보기 재사용
- lib/types.ts 및 권한·재조회 관련 모듈: 필요한 범위만 확장
- supabase/migrations 및 DB 테스트: 콘텐츠·권한·게시 계약
- supabase/functions/_shared/mobile-updates.ts: 공개 다운로드 주소의 호환 확장
- app/globals.css와 public/brand: 현재 테마·브랜드 기준
- lib/update-notes.ts: 제품 구현 시 사용자에게 보이는 변경 안내 추가

경로는 현재 소스 기준 접점이며 확정 파일 분할은 구현 전에 정한다. 모바일 소스·APK 재빌드는 이 웹 기능만을 위해 요구하지 않는다.
